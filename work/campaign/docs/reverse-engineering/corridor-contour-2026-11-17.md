# Исходный контур коридора — 2026-11-17

**Результат:** восстановлены топология и данные всех 16 масок единичной ячейки для заполненного preview, все углы которого допустимы. `godot/scripts/native_corridor_contour.gd` предоставляет чистую функцию `build_triangles(samples: Dictionary) -> PackedVector2Array`: ключи — выбранные `Vector2i` samples, значения не используются; выход — native X/Y, каждые три вершины образуют исходный треугольник. Дополнительные `cell_mask` и `cell_triangles` позволяют проверить формат независимо от сцены. Модуль не создаёт marks и не выбирает задания.

Источник — установленный `C:/Program Files (x86)/Steam/steamapps/common/Diggles The Myth of Fenris/Diggles.exe`, SHA-256 `58a01d3d80670a6042c66a82684397c98e39c503e00a6e2c2c511f338a30ed74`, ImageBase `0x400000`. Ниже preferred VA; при ASLR: `module_base + VA - 0x400000`. Текстовая копия: `tools/.cache/diggles-text-disassembly.txt`.

**Подтверждённый формат.** В `0x56D118–0x56D120` ветка сохранённого штриха берёт `A,E` и задаёт флаг заполненного режима `0`. `0x56D166–0x56D173` добавляет одноклеточную рамку вокруг samples. В `0x56D402–0x56D45D` валидатору передаются `(x,y)`, `(x+1,y)`, `(x,y+1)`, `(x+1,y+1)`; `0x56D46C–0x56D481` передаёт четыре значения в `0x56AE30` в том же порядке. В локальной маске модуля это:

```text
TL=1 (x,y)       TR=2 (x+1,y)
BL=4 (x,y+1)     BR=8 (x+1,y+1)
```

Числа 1/2/4/8 здесь — биты позиции угла, не terrain nibble. Preview-буфер заполняется байтом `1` (`0x56D235–0x56D236`), а отказ валидации добавляет preview-бит `8` (`0x56D414/42F/449/469`). Этот бит имеет иной смысл, чем бит формы пещерной terrain-метки. `0x56AE30–0x56AF77` разделяет допустимые/недопустимые углы на два прохода. Публичный контракт переносит **полностью допустимый проход с заливкой**; не следует использовать его как доказанный генератор смешанного красно-зелёного preview.

**Диспетчеризация.** `0x568420–0x5684F4` считает ненулевые углы: 0 — ничего; 1 — `0x56A027`; 2 — `0x5684FA`; 3 — `0x569279`; 4 — `0x56A97C`. Диагональные пары 6/9 в `0x5684FA–0x568539` рекурсивно разделяются на два одиночных случая через вызов `0x568526`. Никакой диагональной перемычки между компонентами нет. **Данные геометрии.** Полный массив координат и индексов для каждой строки таблицы находится в литералах `_VERTICES/_INDICES` модуля. Это данные исполненных ветвей EXE, а не нарисованная таблица marching squares.

- Четыре угла: вершины `(0,0),(1,0),(0,1),(1,1)`; индексы `012,123`. Запись координат `0x56A9BC–0x56AD23`, индексов `0x56AD67–0x56AE19`. Нативный порядок индексов сохранён, нормализация winding не выполнялась.
- Два соседних верхних угла (маска 3): `(0,.30),(1,.30),(0,.49),(1,.49),(0,0),(1,0)`; индексы `012,123,234,345` (`0x56853E` и последующая ветка записи). Маски 5/10/12 — соответствующие вертикальные/нижняя ветви исходника. В индекcах сохраняется перекрытие полосы края и заливки; объединение полигонов удалило бы исходный overdraw.
- Один угол: веер вокруг выбранной вершины с четырьмя сегментами по `pi/8`. Для TL начальный угол `-pi/2`, для TR `-pi`, BL `0`, BR `pi/2`; локальная точка `C + (cos(angle)*r, -sin(angle)*r)`. Парные радиусы `0.49` и `0.30` (`0x56A027–0x56A4CF`, записи `0x56A2A2–0x56A43C`). Центр, пять пар вершин и исходные 12 треугольников сохранены. Например, первая пара TL приблизительно `(0,.49)/(0,.30)`, следующая внешняя точка `(.1875148863,.4527009726)`.
- Три угла: генератор работает от отсутствующего угла; три радиальных положения через `pi/4`, среднее умножается на `sqrt(2)` (`0x569279–0x569726`). Радиусы `0.51`, `0.70`, `1.0` (`0x5693F3–0x569689`). Это исходный двухсегментный угол с miter, а не произвольная круглая выемка. Для маски 7 характерная средняя внешняя точка `(.49,.49)`.

Константы EXE, прочитанные как little-endian float32: `0x737060 = .3000000119`, `0x737088 = .4900000095`, `0x737098 = .5099999905`, `0x7370B0 = .6999999881`, `0x7371A0 = 1.4142135382`, `0x7370D0 = .7853981853`, `0x7371E0 = 1.5707963705`, `0x737744 = -1.5707963705`, `0x737790 = -3.1415927410`. В буфер вершин пишется Z `0x41680000 = 14.5` (`0x56AA35` и аналоги); функция возвращает только X/Y и не навязывает это число Godot local Z без преобразования пространства.

**Сборка из samples.** Каждый sample является углом четырёх единичных ячеек; модуль обходит их общую рамку построчно и раскрывает исходные индексы в triangle list. Внутренние ячейки не получают независимых обводок-плиток: форма задаётся маской четырёх samples. Для `{5,6}×{9,10}` девять масок по строкам: `8,12,4 / 10,15,5 / 2,3,1`, всего 66 треугольников. Статическая рамка до последующей анимации приблизительно `(4.51,8.51)..(6.49,10.49)`, то есть ширина 1.98 для двух samples по оси. Для `{5..10}×{9,10}` — 106 треугольников. Эти размеры следуют из восстановленных ветвей, не из старого UI-шага 2.5.

**Метод и предел численной точности.** Через `pefile/capstone` выполнена ограниченная интерпретация инструкций `0x56AE30` и `0x568410` для всех масок. Accessor массивов `0x405DD0/0x462CB0` заменены адресной арифметикой для stride 16/2; буферы заранее достаточны. Целочисленные ветвления, записанные индексы и SSE float32-округления перенесены; для каждого входа подсчитаны фактически записанные vertices/indices. Результаты для ненулевых preview-значений `1` и `3` совпали во всех 16 допустимых масках. Plain quad дополнительно сверён с отдельными инструкциями writer.

Два математических вызова заменены `math.cos/sin` хоста. Идентификация подтверждена цепочками `0x6F5AE0 → 0x6F5C87 → 0x6F737F → fcos @0x6F739D` и `0x6F6AD0 → 0x6F6C84 → 0x6F770F → fsin @0x6F772D`. Это **не побитовое воспроизведение MSVC libm и не захват живого рендера**. При переносе локального атласа на `(5,9)` и `(43,23)` максимум отличия от непосредственного вычисления тех же инструкций с этим origin составил `4.76837158203125e-7`. Самотест использует допуск `1e-5`; контракт ограничен положительной картой 44×24. Миниатюрные отрицательные значения порядка `1e-8` на границах сохранены, а не обрезаны как якобы ошибочные.

**Не перенесено / неизвестно в этом ограниченном результате:** исходные RGBA, анимация/колебание поверхности после writer, renderer transforms и смешанная допустимость углов. Модуль не добавляет волну, произвольный цвет, сглаживание или дополнительные shapes. Исходная ветка outline-only проверена по количествам в таблице, но не выставлена в публичный API. Вызов двух независимых атласов для разных цветов не доказан эквивалентным смешанному проходу `0x56AE30`: его общий флаг формы зависит от исходной совокупности четырёх углов.
