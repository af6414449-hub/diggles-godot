# Очередь копания и группы разметки — 0.4.4

17.11.2026. После одного явного назначения первой точки гном продолжает работу через исходный `dig_next`. Контрольная цепочка `(1,15) → (2,15) → (2,16)` дала три завершения анимации и три настоящие мутации BlockDB. Перед вторым ударом гном переместился с X=2.0 на X=2.5: прежняя стойка теряет пол при следующем переходе BDB.

## Подключённая исходная часть

`native_dig_next.gd` ранжирует полный snapshot текущей разметки по core `0x597B20`. Контроллер передаёт native XYZ — Godot Y отражается обратно, Z остаётся логическим. Стоимость, float32-округления, окно сканирования и Y→X-порядок равенств не заменяются расстоянием до ближайшей метки. Snapshot содержит явный mark-word для каждой точки scan_rect; для отмеченного кандидата — известный материал, актуальный Hnext четырёх refs и packed group-word. Отсутствующее terrain-состояние не превращается в пустую/твёрдую клетку: результат `unknown` останавливает продолжение, сохраняя метки.

После выбора сохраняется полный XYZ результата, затем применяется исходное `{0 0 -1}` **после** native clamp Z. В примере следующие цели имеют Z=13; это значение участвует и в ориентации, а не теряется при преобразовании к XY. `dig_check` выделен отдельно от проверки расстояния удара: как в Tcl, проверка трёх соседей сама не содержит радиуса досягаемости. При отказе выбирается следующий ранг; try>6 сбрасывает worker group, предел обычной попытки — девять рангов. `dig_continue` вызывается после завершения action даже при отклонённом ударе, который удалил устаревшую метку.

Доказательства ranking/Tcl: `native-dig-next-2026-11-17.md/.json`. Этот перенос не является live-трассой оригинальной игры.

## Группа — поле мира, а не ID гнома

Из EXE восстановлены конструктор mark manager, point-writer и хвост mode1 commit: `native-worker-group-2026-11-17.md/.json`. `native_dig_groups.gd` моделирует свежий менеджер с восемью dword-счётчиками и packed group-word каждой клетки. Коридорный point-writer заменяет только выбранный nibble на `counter[slot]&15`; один завершённый штрих увеличивает счётчик один раз, включая полностью отклонённый commit. Preview и отмена его не увеличивают. Очистка завершённой метки сохраняет группу.

Группа свежего/явно сброшенного работника — −1. После принятого удара core присваивает **`u32(groups) >> (4*slot)` без `&15`**. Добавлено приведение к u32 перед сдвигом, чтобы отрицательный 64-битный GDScript int не дал арифметический SHR. Кандидат в dig_next читает отдельный nibble с `&15`; эта асимметрия оригинала сохранена. Отклонённый удар stamp не обновляет. Следующий job сохраняет его; reset происходит на завершении/отмене и в исходной try>6 ветке. Ручная новая команда явно прерывает/сбрасывает прежнюю работу — это граница host-контроллера, не утверждение о reset внутри native `dig_starttask`.

В активном UI подключён slot0 (owner/layer 0/0). Остальные slots проверены чистой моделью, но их отображение на нынешние owner/layer и cave commits ещё не перенесено. Счётчики/слова принадлежат явно новому миру, а не извлечены из PMP или произвольного save. Announce не подменён ID группы; полный reservation-протокол оригинала не восстановлен.

## Сохраняющийся пол

`preview_accepted_step` применяет тот же terrain kernel к частной глубокой копии runtime facts. Неизменяемые исходные metadata/меши разделяются; реальные refs, revision и tunnel-validator не меняются. Для четырёх прогнозируемых блоков извлекаются исходные треугольники пола на текущем Y=14.5. Планировщик использует только стойки, имеющие пол и до удара, и после него. Это проверенный floor-adapter вместо выбора стойки поверх будущей пустоты; это **не** восстановленный `vector_fixdig` или гравитация/многоуровневая навигация.

Рабочий пример: текущая стойка `(2,14.5,12)` для цели `(2,15)` имеет пол до удара и теряет его после. Планировщик выбирает `(2.5,14.5,12)`. После следующей цели `(2,16)` этот пол сохраняется. Рендер, collision и доступность по-прежнему перестраиваются по реальным новым refs, не по preview.

## Границы интеграции

- Bounds берутся у **нашего standalone runtime** `[0,44)×[0,24)`. Они не объявлены глобальными bounds оригинальной карты: шаблон принимает `$xoffset/$yoffset`, их реальные значения и окружающий мир ещё не восстановлены. Native scan исключает край шириной две клетки; например, X=1 может быть вручную первой целью, но не последующим auto-кандидатом. Не все отмеченные у края точки поэтому автоматически завершаются.
- Первая цель явно назначена пользователем; `get_digedge` с неизвестным player-byte и native `vector_fixdig` не подменены новым поиском. Первая цель пока использует прежний host Z по текущему профилю; следующие цели хранят полный source XYZ.
- Маршрут/стойка остаются A* одного пола. Отсутствие безопасного подхода вызывает переход к следующему рангу; native walk-failure/restart через get_digedge и лазание ещё не перенесены.
- Запрет взять занятую другим гномом точку — прежний явный host reservation. Точка остаётся в исходном ranking, после отказа рассматривается следующий ранг. Это не реализация всех побочных эффектов `gnome_announce_dig`.
- Рабочий executor продолжает только corridor3; cave marks не превращаются в обычный коридор. Один принятый удар на завершение action и 12 FPS остаются адаптерами. RNG, аварии, инвентарь, attachment кирки и полноценный индивидуальный AI не добавлены.
