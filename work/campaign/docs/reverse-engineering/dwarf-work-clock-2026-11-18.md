# Игровые часы, потребности и первый цикл автоматической работы — 18.11.2026

В multiplayer включена минимальная автоматическая работа: свободный гном на смене выбирает отмеченный забой, подходит к нему и копает через существующую очередь/actions. Конец смены прекращает автоматическое продолжение после текущего удара. Ручной приказ имеет отдельное происхождение и продолжает копание вне рабочего времени. В HUD добавлены 12-часовые часы.

Это ограниченный рабочий цикл, не полный индивидуальный или клановый ИИ. Реестр рабочих мест оригинала, полная машина целей досуга, поиск еды/кровати и разговоры ещё не перенесены. В свободное время текущие гномы сохраняют прежние idle-анимации; потребности уже меняются по исходным формулам.

## Что установлено по EXE

Использован установленный `Diggles.exe`, SHA-256 `58a01d3d80670a6042c66a82684397c98e39c503e00a6e2c2c511f338a30ed74`. `tools/export_dwarf_life_contract.py` проверяет hash и сохраняет девять полных диапазонов инструкций в `godot/models/native_dwarf_life.json`.

| Участок | Правило |
| --- | --- |
| Регистрация `0x61A1A5`, callback `0x6341F0`, значение `0x6342A6..0x6342BB` | `gettime` возвращает double manager+0xA088. |
| Регистрация `0x61A1DF`, callback `0x6343B0`, значение `0x634466..0x63448A` | `gethours` переводит seconds в float32 и делит на float32 **150.0** по адресу `0x737630`. Часы не ограничены 12 при этом getter. |
| `0x565490..0x5654CB` | Нормализованный час — float32(fmod(hour,12)/12). |
| `0x5CB760..0x5CB996` | Start/duration хранятся в actor+0x354/+0x358. Значения приводятся к сетке **floor(2*x+0.05)*0.5**, затем нормализуются к циклу12. |
| `0x6F6DE0..0x6F6E33` | Положительная ветка вызванного helper отбрасывает дробную часть: это floor, а не округление к ближайшему. |
| `0x6956AC..0x695741` | При рабочем флаге actor+0x35D sparetime=0; иначе расстояние до следующего start возвращается в часах. |
| `0x68B4EB..0x68B6C3` | `set_worktime` меняет исходные start/duration поля. |

Один час равен 150 игровым секундам, полный 12-часовой цикл — 1800. Обычное окно включает начало и исключает конец; переход через12 поддерживается. Особенность исходной формулы: duration12 после modulo становится0, а не «работать весь цикл». Она сохранена в arithmetic contract. Используются явные float32 границы SSE.

Константа bias равна **0.05**, не0.5. Поэтому, например,0.3 часа переходят в0, а0.49 — в0.5. Заменять этот участок обычным round(x*2)/2 было бы ошибкой.

Это статический анализ. Полная система native event flags +0x35C/+0x35D, временные overrides и live capture запущенного оригинала не объявляются воспроизведёнными.

## Потребности по исходным Tcl

`zwerg.tcl:183..187` задаёт отдельные таймеры; attribute update вызывается раз в **1 игровую секунду**. `zwerg.tcl:34` задаёт birthtime=gettime−1200. `calc_age` в `z_procs.tcl:1780` считает разность игровых секунд, а не минут. Значения interval/birth age извлечены экспортёром из Tcl.

Default attributes прочитаны из `misc/genattribs.tcl:21..24`: здоровье1.0, сытость0.9, бодрость0.9, настроение0.8. Это class defaults для текущих тестовых акторов, не восстановление индивидуальных значений из сохранения оригинала.

Перенесены строки `z_events.tcl:1775..1880`: здоровье от голода/усталости, настроение, возраст, расход по занятию, disappointment, fun-items и human modifier. При работе за тик: alertness−0.00022, nutrition−0.00025, mood−0.00012. При другом занятии: −0.00017, −0.000195, −0.00004. Дополнительные hunger/age/mood terms применяются отдельно в исходном порядке.

Важно: `trap_mode!=0` запрещает применение **всех четырёх** изменений; заготовка Minimax этого gate не имела. Mood classification вычисляется до add_attrib, как в исходнике. Данные хранятся независимо для каждого актора и публикуются в metadata `needs`, `common_mood`, `current_time_plan`, `work_shift`, `current_occupation`.

Проверка не повторяет формулы Python-пересказом: экспортёр исполняет исходные Tcl-блоки системным Tcl8.6.12 на15 комбинациях needs/context. Native get/add_attrib заменены явно заданными чтением и clamp0..1. GDScript сравнивается с результатами этого oracle. Точность native хранения атрибутов в памяти пока не установлена; host использует double arithmetic и явный clamp.

## Смены и начальная конфигурация

Блок `std_ai.tcl:1523..1549` исполняется Tcl oracle для20 наборов count/hour. В нём длительность смены6, первая позиция int(gethours)%12+7, а интервалы берутся из исходной таблицы. Для одной готовой группы исходник ничего не переназначает.

Начальный bootstrap нашей сцены **явный адаптер**: три текущих актора рассматриваются как отдельные, уже упорядоченные непарные записи с одинаковыми class-default потребностями. При time0 исходный assignment block даёт начала7,1,4 и длительность6 каждому. Native `auto_choose_workingtime` имеет отдельный алгоритм распределения населения; он не перенесён. Пол/отношения текущих тестовых акторов, pairing и индивидуальная initial population оригинала не выдумываются.

Периодическое клановое перераспределение пока не включено. В исходнике его gate — `iTickCounter%4` и `iTickCounter%120==4` (`std_ai.tcl:1234..1240`); комментарий «каждые3часа» сам по себе не доказывает частоту внешнего AI counter.

## Исполнение и приоритет приказов

`native_work_clock.gd` хранит elapsed game seconds; pause/time scale задаются host явно. В `_process` movement, mining, actor tasks, needs и torch timer получают игровой delta, камера сохраняет обычное управление. Во время паузы новые команды остаются в очереди, а движение, mining callback и needs timer не продвигаются. HUD справа показывает HH:MM и «Пауза».

Поля сцены для проверки в Godot Inspector: `autonomous_dwarf_work` (включено по умолчанию), `simulation_paused`, `simulation_time_scale`. Отдельные новые клавиши или мобильные кнопки не добавлены.

`dwarf_life_runtime.gd` удерживает независимые models/timers. Потребности обновляются по накопленным секундным границам, не раз за render frame. API `seek` служит инициализации fixture/save clock и намеренно не проигрывает пропущенное время. Полный native fixed-step scheduler, catch-up ordering, render interpolation и синхронизация всех FX не перенесены.

Минимальный producer автоматической работы вызывается на heartbeat. Он использует восстановленный **native dig_next cost/ranking** и существующий scene frontier/action controller, пропускает занятых/вне смены акторов и зарезервированные точки. Однако клановый `gnome_idle`/available-work registry не восстановлен: частота producer, выбор доступного задания из текущих импортированных marks и cache отвергнутых областей — host embedding, а не заявленная точная копия `std_ai`.

Недоступный автоматический frontier освобождается и не назначается заново до изменения terrain/marks. Такой же frontier по **ручному** приказу остаётся waiting task. Это различие покрыто integration test.

`evt_autoprod_dig_proc` (`z_events.tcl:1514..1541`) задаёт current_worktask="dig"; ручной `evt_task_dig_proc` имеет другой путь. `dig_continue` (`z_dignwalk.tcl:208`) продолжает, если sparetime=0 **или** current_worktask!="dig". В host это выражено происхождением automatic/manual. Начатый обычный strike завершает свой callback; gate применяется перед следующей action/поиском забоя. Ручное копание вне смены не обрывается.

Простое добавление continuation в очередь не считается новым ручным событием. Новое user walk/dig переключает происхождение на manual и использует прежний механизм отмены/stale token. Автоматический producer не забирает актора с выполняющимся или ожидающим ручным заданием.

## Что не включено

Полный выбор досуга в `sparetime_decide_occup` включает future/history, emergency, goal/min-goal и hysteresis. Список `eat/slp/fun` — только начало этого алгоритма. Из заготовки Minimax не перенесён числовой sort вместо исходного строкового `lsort -index 1`; самостоятельно выбирать сон по «самой низкой шкале» main тоже не начинает.

Сон/поиск места, питание, потребление ресурсов, разговоры, забастовка, полная смерть/бой и анимации чувств остаются следующими цепочками. В частности, недостаток здоровья уже влияет на допуск новых автоматических заданий, но исходная death pipeline не реализована. Автоматические паузы рабочего дня этим этапом не следует считать полным поведением оригинала.

Minimax использован только как read-only источник структуры utility/API и указателей на оригинальные строки. Его проект не запускался и не редактировался. Наши age units, trap gate, clock arithmetic и источники проверены независимо.

## Проверки

Новые pure checks:194, в том числе15 Tcl needs fixtures и20 shift fixtures. Реальная main integration:27 проверок — самостоятельный подход/копание, off-duty actor, последний удар после смены, manual override вне рабочего времени, pause/scale, frame partition, trap, HUD pause и rejected-frontier policy.

Полный прогон:19 сценариев,933 проверки с числовым счётчиком плюс native scene-profile pass без такого счётчика. Все завершились без ошибок/предупреждений. Логи: [validation.json](dwarf-work-clock-2026-11-18/validation.json). Статический анализ и три smoke-сцены: [lint.json](dwarf-work-clock-2026-11-18/lint.json), [smoke.json](dwarf-work-clock-2026-11-18/smoke.json).

Старые сценарии ручных actions явно отключают нового автономного producer, чтобы второй свободный гном не забирал их fixture. В трёх input-регрессиях также добавлены проверки enqueue и следующий enabled dispatch: прежнее ожидание немедленного job после клика устарело после предыдущего tasklist этапа. Проверки маршрутов/physics/terrain callback сохранены.

Нового GPU-сравнения освещения этим этапом нет; material acceptance предыдущего этапа остаётся открытым. Проверен текст/состояние HUD, без утверждения pixel parity с оригинальным циферблатом. APK не пересобирался.
