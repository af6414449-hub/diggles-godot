# Восстановленная геометрия грунта BlockDB

Дата: 2026-11-15.

## Результат

Из оригинальных BlockDB0/1/2.BDB восстановлены каталоги блоков, топологии, координаты XYZ/UV и атрибуты вершин. Все три файла полностью разобраны по длине и проверены по индексам. Для hol_024.pmp извлечены 384 ячейки, 115 разных блоков, 4 763 ссылки на вершины и 2 800 треугольников. Исходная упакованная глубина — 7.5–14.5, соответствующая логической глубине 1–15; вертикаль находится в Y карты.

Геометрия и 68 размещений/48 моделей отрисованы в Godot 4.7.2 через OpenGL Compatibility на AMD Vega 8. Актуальные три ракурса и runtime-координаты — native-scene-space/. Исходные текстуры используются для моделей; материал грунта и свет пока диагностические. Android содержит прежний JPEG-прототип.

## Доказательства из EXE

- Tcl map_template зарегистрирован с обработчиком 0x63bca0 (регистрация 0x619d57..0x619d77).
- Обработчик вызывает загрузчик 0x5992b0. Он читает размеры, N байт флагов, N u32, массив u16 и дополнительный байт на ячейку.
- В 0x599a92..0x599b3e значение u32 из PMP переносится в первое поле runtime-ячейки. Это поле раньше называлось cell_refs без установленного назначения.
- В 0x4093f0..0x409447 первое поле runtime-ячейки используется как индекс в метаданных BlockDB с шагом 89 байт. Первые 64 байта записи адресуются как сетка 8×8: (y & 7) * 8 + (x & 7). Caller ниже подтверждает, что эти значения участвуют как высотные сэмплы; точные единицы и их связь с визуальными гранями пока не установлены.
- Caller 0x4097b0 сравнивает логическую глубину с 8×8 сэмплом. Прежний вывод, будто это физическая вертикаль, был неверным. Native terrain emitter 0x4ca658..0x4ca670 добавляет column/row к X/Y; Z остаётся отдельной глубиной. EXE 0x409baf кодирует z_render=7+z_logical/2, а 0x64c646..0x64c65b выполняет обратное преобразование. Адреса, байты и границы доказательства — bdb-axis-evidence-audit.md.
- CBlockDB::LoadDB находится в 0x565ab0. В 0x565c05..0x565e75 явно заданы размеры секций; в 0x565ed1..0x565efd — отдельные массивы u16 vertexID и u8 атрибутов каждой части.

Сохранённые выдержки: blockdb-loader-disassembly.txt, pmp-loader-disassembly.txt, pmp-loader-tail-disassembly.txt, pmp-block-reference-access.txt, map-template-command-disassembly.txt. Полный дизассемблированный EXE находится только в игнорируемом tools/.cache/; это промежуточный анализ, не переносимый код.

## Раскладка BDB v11

Все значения little endian. Заголовок: семь u32 — версия, неизвестное поле, количество блоков, неизвестное поле, количество индексов, количество топологий, количество глобальных вершин.

1. Для каждого блока три записи: u16 количество вершин и u32 идентификатор топологии.
2. По 89 байт метаданных на блок.
3. Общий массив u16 локальных индексов треугольников.
4. Таблица топологий: u32 начало и u32 количество индексов.
5. Общие вершины: пять float32 — x, y, z, u, v.
6. Для каждого блока и каждой части: u16 vertexID[количество], затем u8 атрибут[количество].

В каждой базе 118 688 блоков. Базы различаются плотностью геометрии; соответствие номеров качеству изображения ещё не установлено. Части 0/1/2 сохраняются отдельно. Атрибут u8 — индекс нормали в sphere.dat; загрузка таблицы и использование подтверждены EXE. Назначение последних 25 байтов метаданных ещё исследуется.

## Проверки

- Точный EOF всех трёх баз, без хвоста.
- 173 044 топологии, 1 068 192 части и 10 448 382 ссылки vertexID проверены без ошибок.
- Все индексы топологий и треугольников в допустимых пределах; XYZ/UV конечны.
- JSON hol_024 занимает 132 979 байт и сохраняет ссылки ячеек на исходные блоки.
- Счётчик построенной Godot-геометрии должен совпадать с экспортированными 2 800 треугольниками; при несовпадении запуск прекращается.
- Линтер и проверка проекта: 0 ошибок, 0 предупреждений. Финальный графический запуск завершился без ERROR/WARNING, сохранил три ракурса. Первая попытка выявила числовые JSON-ключи и ограничения кеша песочницы; они устранены перед финальной проверкой.

Подробные смещения, SHA-256 и счётчики: blockdb-layout-audit.json.

## Инструменты и воспроизведение

tools/inspect_bdb.py — ленивый BdbDatabase, проверка баз и экспорт отдельного блока в OBJ.

tools/export_pmp_terrain.py — PMP + BDB → манифест настоящих мешей. Сборка контрольного шаблона из корня проекта:

```powershell
python tools/export_pmp_terrain.py 'C:\Program Files (x86)\Steam\steamapps\common\Diggles The Myth of Fenris\data\Templates\hol_024.pmp' 'C:\Program Files (x86)\Steam\steamapps\common\Diggles The Myth of Fenris\data\BlockDB2.BDB' godot/models/hol_024_terrain.json
```

Сцена: godot/scenes/terrain_reference.tscn. BDB (local_x,local_y,packed_depth) сначала переводится в логические (cell_x+x,cell_y+y,2*z-14). Tcl уже содержит логические X/Y/Z. Godot использует (x,-y,z), затем общий корень применяет z_render=7+z/2. Отражений X/Z и перестановки Y/Z нет. Исходные нормали берутся из sphere.dat. Проверка tools/audit_scene_space.py: 531/531 угловая вершина, 12 ячеек пола на Y=10.5, оба настенных факела на 0.005 перед стеной. Этим устранён прежний серый занавес поперёк сцены; материал грунта и повороты/масштаб моделей остаются отдельной задачей.

## Сверка с оригиналом и объекты demo_start

Пользователь передал три ракурса одной стартовой пещеры; описание, исходники и выводы сохранены в `visual-reference-2026-11-15.md` и `reference-images/`. Повторно запрашивать скриншоты для этого этапа не нужно.

`export_demo_start_models.py` теперь проходит правильную цепочку 3DB: именованный объект → индекс анимации → индекс кадра меша. Прежняя ошибка подставляла индекс анимации вместо меша и рисовала дворцовые арки вместо мха. После исправления из `Templates/demo_start.tcl` экспортированы 64 сопоставленных размещения, 47 моделей и 45 оригинальных текстур, включая Feuerstelle, Zelt и три статичных Zwerg с представительным мужским mesh. Выбор TGA предпочитает локальный файл с наибольшим разрешением; новые TGA импортированы Godot. Актуальный рендер — `animation-index-corrected/`. Старые кадры с арками являются результатом ошибки импортера.

Повторный аудит 47 правильно выбранных мешей сравнил float32 bounds из 3DB с декодированными u16 point-массивами. Для 136 из 138 ненулевых осей масштаб `16384 * (point - 0.5)` совпадает с bounds в пределах 1%; медианное отношение — 16394.7. Это восстанавливает масштаб хранения координат в модели, но не итоговый размер в мире: неизвестный object/class transform может компенсировать масштаб. Поэтому множитель 100 в рендере пока остаётся предварительным. Bounds сохраняются в `demo_start_models.json`; аудит воспроизводится `python tools/audit_3db_bounds.py`.

Отдельный OBJ-экспорт `inspect_3db.py` теперь использует 16384 и выдаёт координаты в единицах mesh bounds. Godot-сцена пока использует свой world-scale множитель 100: его правильность для размещения нужно вывести из движка, поэтому OBJ-масштаб не перенесён в сцену автоматически.

Рендер пока не соответствует оригиналу по материалу грунта, освещению, ряду поворотов/вариантов и runtime-состояниям моделей. Геометрию исправляют по source/EXE-аудиту, не подбором общего зеркала. Part 0 нельзя выбрасывать: он включает заднюю стену. Части 1/2 содержат разнонаправленные переходы, включая пол и потолок; их отсечение не заменяет корректные координаты.

При разборе обнаружены два разных `demo_start.tcl`: `Templates/tcl/demo_start.tcl` не содержит `map_setlayer2`, а editor wrapper `Templates/demo_start.tcl` содержит ссылку на `demo_start.l2m`. Сам файл `data/Templates/demo_start.l2m` в установленной игре отсутствует. Байтовые атрибуты BDB распознаны как нормали sphere.dat. Последние 25 байтов метаданных и материалы требуют дальнейшего разбора; нельзя назначать текстуру стен только по визуальному сходству.

Дополнительно проверены группы ячеек PMP `flags=0x02`, `0x04`, `0x84` раздельно при той же камере и отсечении обратных граней. Их геометрия даёт соответственно 374, 191 и 2 235 треугольников; сумма ровно 2 800. Сводка кадров — `terrain-flag-2/`, `terrain-flag-4/`, `terrain-flag-132/`. Разделение показывает разные наборы границ и внутренних поверхностей, но пока не устанавливает семантику флагов; фильтр используется только для диагностики и не включён в финальную геометрию.

Автоматическая проверка исходных байтов: `python tools/audit_scene_space.py`; результат — scene-space-audit.json.
