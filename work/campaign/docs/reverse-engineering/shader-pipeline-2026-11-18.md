# Lighting pipeline continuation — 2026-11-18

## Runtime change

Recovered terrain lighting is now the ordinary multiplayer startup mode. This supersedes the opt-in decision in terrain-render-2026-11-18.md. Two independently verified omissions explained much of the previous darkness: source lamp color units, and the Steam port gamma stage. No exposure multiplier was fitted to screenshots.

The scene root still exposes `Native Terrain Lighting Preview` for comparison. Turn it off, or launch with `--legacy-terrain-lighting` after Godot's `--`, to use the earlier Godot-lit terrain material. The explicit `--native-terrain-lighting` flag remains available. Prop/dwarf materials retain their previous lighting adapter; this change applies to terrain.

## Original files that changed the conclusion

Read directly from the installed game:

- `data/Shaders/Common.fxh`: two texture stages begin with diffuse color; operator definitions and argument selection. No clamp is inserted by this shader between the stages.
- `data/Shaders/UL2CS.fx` / `TL2CS.fx`: unpack both vertex colors, apply texture stages, add enabled secondary RGB, then AlphaTest and ApplyGamma.
- `data/Shaders/Gamma.fxh`: `pow(rgb, 1/gamma)`, then saturate after brightness addition. This is the game's gamma formula, not an assumed sRGB transfer.
- `data/Shaders/Composition.fx`: bloom and scene-brightness-dependent blue/green modulation are a separate path, still unported.
- `DigglesPort.dll`, SHA-256 `ace39618ac4946454eadaf35a824144c67b525ccafffad8a19ad200b3fdb6cf3`: GammaManager setter 0x1000C860 converts the first raw option through `/100 *2 + .3`, the second through `/100 -.5`.
- EXE settings loader 0x6AFD2D..0x6AFE28 uses fallback 50 for both raw settings. EXE calls the port at 0x465614..0x465634. Float32 default gamma is 1.2999999523162842, brightness zero. The user's live original-game settings were not captured. The legacy configuration key names/call parameter naming differ; no personal slider values are inferred.

All files and PE spans are hashed in `native-shader-pipeline-2026-11-18.json`, generated by `tools/export_native_shader_pipeline.py`. --check is read-only and also pins the original EXE and port DLL versions.

## Lamp-unit chain — the main intensity bug

| Stage | Source evidence |
|---|---|
| Tcl class_light | Registration 0x61088D -> callback 0x614990. For RGB, e.g. 0x614CBC..0x614CD1: float32 multiplication by constant 31 at 0x7375A8, truncation to signed int, store class+0x3C/+0x40/+0x44. |
| Class to object | 0x5C7CF9..0x5C7D14 copies those integer channels into object+0x298/+0x29C/+0x2A0. |
| Object to light pool | 0x5CC0D0..0x5CC112 pushes all three integer channels into 0x591A20. 0x591CF3..0x591D05 stores them into the 36-byte light record +0xC/+0x10/+0x14. |
| Pool to terrain renderer | 0x4C80FD..0x4C810F converts the integer channel to float and multiplies by .5; green/blue follow the same pattern at 0x4C8153..0x4C81A9. |

Therefore `{.6,.6,.5}` reaches terrain evaluation as `{9,9,7.5}`, not the normalized Tcl tuple. Fire-bowl `{.7,.6,.4}` becomes `{10.5,9,6}`. The former adapter underpowered nearby lamps by roughly fifteen times. The normal-dependent base and radius attenuation remain the recovered EXE formula; their constructor gain was not increased.

Class light positions/ranges are still literal initial Tcl values. Dynamic light changes, object enable state and exact source visibility/owner bytes remain unported; imported crop lighting uses the explicit explored-strength assumption from the previous report.

## Second vertex color and shader

EXE 0x4CC52C..0x4CC5C2 splits rounded channel values into diffuse clamped to 0..255 and overflow clamped to 0..64. This is not a new Phong highlight. Geometry now exports secondary RGBA32F through CUSTOM0 on every vertex. The vertex shader interpolates its RGB; the fragment shader adds it after texture staging and before gamma, as UL2CS does.

`native_terrain_pipeline.gdshader` is separate from the ordinary legacy detail shader. This removes fragile source-string replacement of fragment expressions. It implements the source operators used by the explicit stage program and several other Common.fxh arithmetic operations.

**Still an explicit host assumption:** the active terrain draw-state opcodes/arguments have not yet been independently traced. The current program remains ground MODULATE diffuse, then detail MODULATE2X current. The former adapter applied an early clamp before illumination; the new pipeline follows the source operation order without that invented intermediate clamp. Specular-enable state is assumed enabled for the secondary field. Full alpha test, custom stage selectors and all other Common.fxh operations are not claimed.

The new default is a more complete, evidence-backed terrain approximation, not a claim of pixel-identical original rendering. Crop-edge sampling, live RNG, owner/fog, dynamic lights, bloom/composition and model lighting retain the previously documented limits.

- Source numerical fixtures check both lamp conversions, original gamma defaults, saturated diffuse and bounded overflow.

- APK/export settings unchanged; no agents started.
