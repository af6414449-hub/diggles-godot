## 2. Две поправки к спецификации (важно)

Спецификация `docs/plan/raupe-ai-2026-11-19.md` сверена построчно, но в двух утверждениях она перепутана. Порт сделан по оригиналу, а не по спецификации.

### 2.1 `attacktyp`: хищные — это 02/06/07/08, а не девять из тринадцати

Спецификация: «`attacktyp = 0` для `02/06/07/08`, иначе 1 (хищных 9 из 13)».
Оригинал `raupe.tcl:48-52`:

```tcl
if {[land $rtyp {02 06 07 08}]==""} {
    set attacktyp 0
} else {
    set attacktyp 1
}
```

`land` — поиск элемента по списку (подтверждено 30 другими вызовами в игре, например `std_ai.tcl:1460`: `if {[land $gnome $UnavailableGnomesList]==""}` → «нет в списке»). Значит: тип **входит** в список → `attacktyp = 1` → хищный. Типов хищных **четыре**: 02, 06, 07, 08.

Подтверждение вторым концом: `find_plant` выходит сразу при `attacktyp == 0` (`raupe.tcl:119`) — то есть искать растение могут только те, у кого `attacktyp == 1`, то есть ровно четыре типа.

**В порте:** `RaupeAi.PREDATORY_VARIANTS = [2, 6, 7, 8]`, `attack_type()` возвращает 1 для них и 0 для остальных девяти. Тест `native_raupe_ai_self_test.gd` фиксирует таблицу, тест `native_raupe_actor_self_test.gd` проверяет, что тип 05 никогда не входит в `plant_attack` и не наносит урон.

### 2.2 Порядок: гейт видимости стоит **до** поиска растения

Спецификация: «first call `find_plant` … Free roaming is gated by `get_max_fow(this) >= 10`».
Оригинал `raupe.tcl:67-85`: гейт видимости — первая же строка `crawl_free`:

```tcl
proc crawl_free {} {
    if {[get_max_fow this]<10} {return 0}
    ...
    if {[find_plant]} {return}
```

То есть при `get_max_fow < 10` червяк **не делает ничего вообще**: ни блуждания, ни поиска растения. Спецификация переставляла эти два шага местами.

**В порте:** `_crawl_free()` сначала проверяет видимость и выходит, `find_plant()` не вызывается вовсе. Тест: «a blind Raupe asks for no place» + «a blind Raupe does not move».

### 3.2 Таймер классификации — `raupe.tcl:166-178`

Каждую секунду `test_farmed` ищет ферму в AABB `{-2 -0.5 -3 2 0.5 3}` относительно червя (`:64`), после чего состояние переключается на `free` или `farmed`.

### 3.3 Состояния

- `free` (`:207-216`): в инвентаре → `contained`; иначе `crawl_free`.
- `crawl_free` (`:67-85`): видимость ≥ 10 → поворот `yaw + 1.57`, джиттер `rand()*3-1.5`, 20% разворот на `pi`, точка в 2–4 единицах, `get_place(circle 3, nearpos, random 2)`; нет точки → `wait 3`; иначе поворот к цели и `move` со скоростью `0.03`.
- `farmed` (`:218-236`): в инвентаре → `contained`; ферма невалидна или без buildup → `free`; 5% тиков → `wait 1`; иначе `crawl_farmed`.
- `crawl_farmed` (`:87-115`): гном рядом с фермой (AABB `{-3 -0.5 -5 3 0.5 5}`) смещает выбор точки, прямоугольник фермы `x -2..1.5`, `z -3..3`, `mindist 0.6`, `random 2`; нет точки → `wait 3`.
- `contained` (`:238-251`): пока в инвентаре → `wait 4`; освобождён → `free` или `farmed`.
- `plant_attack` (`:253-319`): HP < 0.01 → удаление; инвентарь → `contained`; растение пропало → `free`; иначе фазы: подход (`0.55 ± 0.1`) → замах (кадр 5 или 9, 0.5 или 0.9 с) → укус (`-0.03` растению, `-0.05` себе, частицы 15) → повтор.

## 4. Порт в GDScript

### 4.1 `native_raupe_ai.gd` — правила

Чистые статические функции без зависимости от сцены: `variant_tag`, `attack_type`, `is_predatory`, `vector_xz`, `angle_xz`, `yaw_towards`, `yaw_away`, `free_turn`, `free_reverse`, `free_candidate`, `free_place_request`, `farm_rectangle`, `farm_place_request`, `attack_counter_step`, `attack_frame`, `windup_seconds`, `attack_finished`, `approach_point`, `attack_particle`, `farmed_wait`, `place_failed`, запросы `farm_query` / `dwarf_query` / `plant_query`, `move_request`, `anim_clip`.

Соглашения по углам выведены из самого оригинала и взаимно согласованы:
- `get_anglexz(a, b) = atan2(b.x - a.x, b.z - a.z)`, вектор `get_vectorxz(θ, l) = (sin θ, 0, cos θ)·l`;
- модель оригинала смотрит по локальной оси +X, поэтому `roty = угол − 1.57` (`raupe.tcl:81`), а `roty = угол + 1.57` — для разворота от растения (`:285`).

### 4.2 `native_raupe_actor.gd` — актёр

Машина состояний `free / farmed / contained / plant_attack`, 1-секундный таймер классификации, собственный MT19937 (`diggles_irandom.gd`) с собственным seed, трасса событий и снапшот состояния.

Адаптер к миру (все вызовы необязательны):
`actor_pos`, `max_fow`, `is_contained`, `owner_id`, `query_farm`, `farm_state`, `query_dwarf`, `query_plant`, `plant_state`, `pick_place`, `damage_plant`, `emit_particles`, `destroy_actor`, `move_action`, `move_complete`, `play_clip`.

Публичные методы: `setup(adapters, seed)`, `tick(delta)`, `get_state`, `get_variant`, `get_variant_tag`, `get_attack_type`, `get_hitpoints`, `get_anim_mode`, `get_attack_plant`, `get_approached`, `get_yaw`, `get_farm_id`, `get_trace`, `set_variant`, `set_owner`, `set_farm`, `set_contained`, `get_state_snapshot`, `restore_from_snapshot`.

Червяк **не является** подклассом хомяка: у него своя машина состояний, свой анимационный контракт (`standard` / `kriechen`) и свой адаптер.

### 4.3 `native_farm_raupe.gd` — сторона фермы

Состояние фермы: `farm_counter`, `worm_fodder`, `original_worm`, `last_creation`. Методы: `candidate_request`, `actualize_worm`, `production_plan`, `apply_creation`, `can_recreate`, `register_creation`, `recreate_request`, `free_original_worm`, статика `threshold`, `inventory_removal`.

## 6. Инженерные адаптации (не факт из оригинала)

1. **Таймер классификации не прерывает текущее действие.** В оригинале `evt_timer0` переключает состояние каждую секунду; видно ли в движке, применяется ли такой триггер во время действия (`state_disable`), по Tcl-исходникам нельзя. В порте триггер не прерывает действие, потому что оригинал ждёт 4 с в инвентаре, а цикл атаки длиннее секунды; без этого правила документированная атака по растению была бы недостижима.
2. **Атака не прерывается классификацией.** Пока цель жива, секундный таймер не переводит червяка из `plant_attack`. Следствие — то же, что в пункте 1.
3. **Условность «гном был»** в порте задаётся адаптером (`farm_state`, `query_dwarf`), в оригинале это флаг `gnomewashere` фермы.
4. **Смысл кодов `get_place`** перенесен как есть (`<0`, `<1`, `>0`), но в порте код возвращается адаптером числом, а не элементом списка Tcl.
5. **Частицы**: оригинал зовёт `create_particlesource 15 pos dir 16 1`; последние два аргумента движком не документированы и переносятся как есть (`amount`, `flag`).

## 7. Чего нет и что осталось неизвестным

- **Геометрия и клипы `raupeNN`** не выгружены из оригинала — отдельная задача после инвентаризации ассетов. Порт держит полный контракт состояний без геометрии: `standard` / `kriechen`, кадры 5 и 9.
- **Червяк не подключён к ферме в игре.** Модуль `native_farm_raupe.gd` реализует правила, но объект Farm в сцене ещё не вызывает их — это следующий шаг интеграции.
- **Мультиплеерная карта не получает червей.** Ни тихих спавнов, ни ручного добавления: `native_raupe_scene_self_test.gd` специально проверяет, что в `multiplayer_test.tscn` и `multiplayer_test.gd` нет упоминаний червя. Появление червей в мире — только из производства фермы.
- **Неизвестно:** точная семантика `get_place` в движке (что именно кодирует первый элемент), поведение `state_triggerfresh` во время действия, смысл `16` и `1` в `create_particlesource`, сетевая репликация состояния червя.
