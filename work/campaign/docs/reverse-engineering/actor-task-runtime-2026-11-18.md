# Очередь действий отдельного гнома — 18.11.2026

Очередь подключена к основной multiplayer-сцене. Обычные приказы ходьбы и копания из обработчика выбора теперь ставят исходные `walk_pos` / `dig_starttask` в tasklist выбранного гнома. Движение, подход к забою и само изменение грунта по-прежнему исполняют существующие проверенные actions. Это основа исполнения действий для будущего ИИ; автономное расписание, потребности и общение этим этапом не включены.

## Исходные правила

В установленной игре прочитаны шесть файлов `data/Scripts/classes/zwerg/`. Экспортёр `tools/export_actor_task_contract.py` сохраняет hashes и исходные строки в `godot/models/native_actor_task_contract.json`.

| Источник | Подтверждённое правило |
| --- | --- |
| `zwerg.tcl:321..335` | Состояние task извлекает один элемент, удаляет его, затем выполняет через eval. Пустая очередь переводит гнома в idle. |
| `z_work_states.tcl:13..23` | Work dispatch сначала обрабатывает tasklist и возвращается; другие ветви состояния не выполняются в этот вызов. |
| `z_events.tcl:336..365` | Новый ручной walk очищает прежнюю очередь, прекращает работу и ставит `walk_pos` с позицией. |
| `z_events.tcl:1019..1058` | Dig event записывает actor-global `current_digpos`, ставит `dig_starttask` и назначает stone hat. |
| `z_procs.tcl:186..205` | `play_anim` вызывает state_disable; callback action включает состояние обратно. Обычный return true завершает Tcl-процедуру сразу. |
| `z_dignwalk.tcl:136..165` | `dig_starttask` использует `current_digpos`, находит край, ставит `walk_pos_dig` и `dig_continue`. |
| `z_dignwalk.tcl:590..605` | `walk_pos` отключает состояние и запускает walk action. |
| `z_spare_fun.tcl:295..307` | Braced idle-команда содержит отложенный `[irandom 4]`; выбор происходит при eval, а не при постановке. |

Важное различие: state_disable блокирует **следующий элемент очереди**, а не дальнейшие команды текущей строки Tcl. Поэтому `play_anim ...; create_muetze ...` инициирует оба вызова в одном eval, и только следующее извлечение tasklist ждёт callback. В новой реализации это правило сохранено. Создание/удаление шапок по всей исходной процедуре пока не перенесено.

## Реализация

`native_tasklist.gd` — отдельный FIFO на актора. Использована структура API заготовки Minimax с проверкой по оригинальным callers. Наши имена методов адаптированы к GDScript. Политика пустой строки для недопустимого индекса остаётся явно host policy; контейнер EXE не объявляется восстановленным.

`native_task_eval.gd` — ограниченный evaluator слов и подстановок. Он сохраняет braces/quotes, scalar substitution, вложенные команды, основные escapes, `;`/newline и порядок эффектов. Подставленное значение не разбивается повторно на команды/слова. Команды возвращают отдельные `code` и `value`: строка `"0"` при code0 не является ошибкой и не прекращает цепочку. Ошибка code1 прекращает текущую строку.

Это не полный Tcl interpreter. Доступны `set`, `string index` с целым индексом и `error`, а остальные команды обязаны иметь зарегистрированный handler. Loops/procs, arrays/namespaces, numeric escapes, общий eval и прочие конструкции не исполняются как будто поддержаны. Для недопустимого синтаксиса/неизвестной команды возвращается явная ошибка. Вложенность ограничена 32 уровнями. Bare scalar names ограничены ASCII; `${...}` поддерживается отдельно.

`native_actor_tasks.gd` извлекает максимум один элемент за enabled dispatch. Async action блокирует следующий dispatch; текущий compound script продолжается. Завершение принимается ровно один раз по токену. Новый ручной приказ очищает очередь и инвалидирует токен: завершение старой анимации не может разблокировать новое действие.

Токены и остановка очереди после ошибки — явные host safeguards, а не декодированные поля native runtime. Частота dispatch пока связана с вызовом основной сцены; точная native state cadence будет связана с game clock отдельным этапом. `source_animation_action.gd` теперь точнее описывает контракт: caller передаёт native timing либо обозначенный action-specific adapter.

`dwarf_task_runtime.gd` связывает очередь с multiplayer actions. Зарегистрированы `walk_pos`, `dig_starttask`, простой `play_anim`, `irandom`, а также `tasklist_add`, `tasklist_addfront`, `tasklist_clear` для `this`. Finite play использует подтверждённую частоту native animation controller. Idle renderer не перекрывает такую анимацию. Clip должен реально присутствовать в уже экспортированных ресурсах; наличие alias metadata само по себе не загружает mesh.

Для копания соединённая область считается одним действием: после первой ячейки очередь остаётся заблокированной, а действующий dig_continue выбирает следующий забой. Если подхода нет, assignment сохраняется вместе с blocked queue. При полном завершении области очередь продолжает следующий элемент. Новый приказ освобождает reservation и прекращает старую work animation до её callback — отменённая работа не меняет грунт.

## Границы переноса

Ходьба и копание — embeddings существующих scene adapters, а не дословное исполнение всех Tcl-процедур. `dig_starttask` использует actor-global `current_digpos`, как в исходнике; его внутренние `walk_pos_dig` / `dig_continue` пока остаются существующим region/action controller. Native world offsets и source get_digedge/Calc1 всё ещё имеют ранее описанные ограничения.

Координаты команд в этой сцене используют локальные оси выбранного шаблона, Y вниз. `walk_pos -force`, полный набор action callbacks, переходы work/sparetime, facial animation и battle/death logic не перенесены. Две async actions в одном compound script отклоняются явно: native replacement contract для этого случая ещё не установлен. Async action плюс синхронные команды поддерживаются и проверяются.

`irandom` в main использует Godot RNG; исходный алгоритм генератора не восстановлен. В oracle/integration тестах выбор фиксируется, чтобы проверить время подстановки без случайных результатов и без загрузки отсутствующих idle c/d meshes.

Приказ взаимодействия с бочкой сохраняет прежнюю scene-реализацию, но предварительно отменяет очередь выбранного гнома. Нельзя считать весь интерфейс действий или полный индивидуальный ИИ перенесённым. Остальные акторы сохраняют свои очереди и действия при отмене одного гнома.

Проект Minimax использован только для чтения; его скрипты не запускались и файлы не менялись. Исходные пути и hashes прочитанных queue/dispatcher/notes сохранены в validation. Диспетчер Minimax целиком не копировался из-за ранее подтверждённых расхождений подстановок и completion semantics.

Новые pure tests: **76 проверок**. Новая реальная multiplayer integration: **39 проверок**, включая:

- Два одновременно идущих гнома; завершение walk запускает следующую анимацию, а её completion — следующий элемент.

- Две исходные клетки полностью выкапываются до перехода к следующему элементу очереди.

- Выход из новой шахты сохраняет корректный путь по глубине.
- Неподходящий забой блокирует очередь до отмены; реальный клик по выделению ставит `dig_starttask`.
- Неподдержанный второй async action в одной строке отклоняется явно.

## Следующее приращение

Связать game clock, worktime и внешние interruption events с actor runtime; затем подключить минимальный выбор занятия из исходных потребностей и реальный idle/work dispatch. Материалы Minimax по этим формулам остаются кандидатами для независимой сверки. Для каждого занятия сначала переносить конкретную исходную цепочку и её callbacks, а затем расширять словарь evaluator/экспорт анимаций. Полный интерпретатор всех Tcl не является условием этого ограниченного следующего шага.
