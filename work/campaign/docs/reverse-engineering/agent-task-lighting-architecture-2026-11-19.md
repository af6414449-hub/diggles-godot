# Задача агенту: освещение без фризов

## Контекст

Основной проект: `C:\Users\frant\OneDrive\Документы\ChatGPT\Diggles`.

Godot-порт Diggles уже умеет раскапывать клетки, создавать автоматические
факелы и менять статическое освещение. Но текущая реализация перекрашивает
вершины terrain mesh по чанкам в очереди: это убирает большой фриз, но свет
от нового факела проявляется очень медленно. До этого синхронное обновление
давало заметную паузу после вскопки/активации факела.

Параллельные задачи уже заняты:

- `agent-task-walkmap-performance-2026-11-19.md` — локальный walkmap;
- `agent-task-hamster-integration-2026-11-19.md` — хомяки.

Не менять эти направления и не редактировать игровой код основного проекта.

## Цель

Сначала по оригинальным файлам и исходникам определить, какой тип освещения
использует Diggles для пещеры, факелов и локальных эффектов. Затем предложить
практичную двухслойную архитектуру для Godot:

1. мгновенный визуальный свет нового факела без пересборки terrain mesh;
2. необязательное фоновое точное уточнение/запекание, если оно вообще нужно;
3. отсутствие работы на каждом terrain-чанке при одном ударе кирки.

## Обязательные исследования

1. Найти в оригинальных `*.cpp`, `*.h`, данных и shader/material-подобных
   ресурсах свидетельства о световых источниках, lightmap, vertex color,
   масках, радиусах и обновлении после добычи.
2. Привести короткие точные ссылки: путь, символ/функция либо понятный фрагмент
   логики. Не делать выводы только по скриншотам.
3. Посмотреть текущие Godot-файлы только для предложения интеграции:
   - `godot/scripts/multiplayer_test.gd`;
   - `godot/scripts/native_scene_profile.gd`;
   - `godot/shaders/native_terrain.gdshader`;
   - `godot/scripts/native_flame_emitter.gd`.
4. Сравнить минимум два варианта: shader uniform/массив источников,
   отдельный overlay/light-volume, Godot Light3D. Оценить: стоимость на
   факел, ограничение числа источников, совместимость с source-координатами,
   риск визуальных артефактов на стенах.
5. Выдать конкретный рекомендуемый вариант и минимальный план интеграции,
   но **не вносить изменений в `godot/`**.

## Ограничения

- Не копировать и не заменять целиком `multiplayer_test.gd`.
- Не строить APK и не менять экспорт.
- Не выдавать предположения как факты: помечать уровень уверенности.
- Оптимизация walkmap не входит в задачу.
