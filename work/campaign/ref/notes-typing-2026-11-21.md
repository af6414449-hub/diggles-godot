## 2. Рендерер вложен в сценовый объект по смещению `0x28B0`

`FUN_00464780` (конструктор сцены/дисплея):

```
0x00464979: lea      ecx, [esi + 0x28b0]
0x00464983: call     0x4c4420          ; инициализация рендерера
```

`FUN_004653d0` — то же самое при вызове метода рендерера:

```
0x0046640B: lea      ecx, [edi + 0x28b0]
0x00466411: call     0x4cde30          ; пре-компьют 81 текстуры
```

Контрольная сумма: `0x28B0 + 0x17388 = 0x19C38` — ровно то место, где начинаются поля `CDisplay`
(`0x19C3C`, `0x19C48`, …). Значит рендерер — **член** сценового объекта, а не отдельный объект;
в `ghidra_structs.tsv` добавлено поле `CDisplay 0x28b0 renderer CSceneRenderer`.

## 3. Структура таблицы масок (важно для порта)

`FUN_004c4c50(param_1 /*ushort*/, param_2 /*out maskTex*/, param_3 /*out tex*/, param_4 /*level*/)`:

```
group = (param_1 >> 5) & 7                      ; 8 групп
base  = in_ECX + group * 0x204 + 8
slot  = base + variant * 0x100 + maskIndex * 0x10 ; variant ∈ {0,1}, maskIndex ∈ {0..15}
slot[0] = указатель на массив номеров текстур
slot[1] = количество вариантов в этом массиве
base + 0x200 = дефолтная текстура группы
```

Дефолтные текстуры групп, записанные при инициализации (`FUN_004c4420:89-96`):

| группа | смещение | значение |
|---|---|---|
| 0 | `0x0208` | 0x14 (20) |
| 1 | `0x040C` | 0x14 |
| 2 | `0x0610` | 0x14 |
| 3 | `0x0814` | **0x15 (21)** |
| 4 | `0x0A18` | 0x14 |
| 5 | `0x0C1C` | 0x14 |
| 6 | `0x0E20` | 0x14 |
| 7 | `0x1024` | **0x15 (21)** |

Значит `0x1024` — **дефолтная текстура группы 7**, а не «level» (ошибка прежней раскладки).

Про `param_1` (ushort):
* биты 0..4 — случайное 5-битное значение; выбор варианта = `(param_1 & 0x1F) % slot[1]`;
* биты 5..7 — номер группы;
* биты 8..15 — 4 уровня углов по 2 бита (это байт `CHeightBlock + 0x54`, т.е. `cornerLevels`).

## 4. Выбор текстуры земли

`FUN_004c4ae0(param_1 /*out tex*/, param_2, param_3, param_4, param_5, param_6, param_7, param_8, param_9)`:

```
idx = (((param_5 & 3) * 3 + (param_4 & 3)) * 3 + (param_3 & 3)) * 3 + (param_2 & 3);   /* 0..80 */
if (variants[idx] != 0)
    tex = textures[textureIndex[idx] + ((idx | rand8) >> 8) % variants[idx]];
```

* `idx` — «81 текстура»: 3^4 комбинаций по 4 углам (уровень угла = `значение & 3`);
* `rand8` — байт 8..15 второго аргумента, служит и случайностью, и сдвигом варианта;
* `param_6`/`param_7` — перестановка параметров (0/1/2) для зеркала/поворота;
* `param_9 != 0` — обнуляет случайность (детерминированный выбор).

## 5. Методы CMap

`FUN_00592f10(x, y)` — аксессор клетки, **метод CMap** (`this` = карта):

```
idx  = ((clamp(y) * map->mapWidth) + clamp(x)) % map->cellCountTotal;
cell = map->cells + idx * 0x7C;                 /* размер CMapCell = 0x7C */
```

Клампы: `x` в `[map->cellX0, map->cellX1)`, `y` в `[map->cellY0, map->cellY1)`
(`0x84/0x8C/0x88/0x90`). Это подтверждает `CMapCell` ровно 0x7C байт.

`FUN_004093f0(x, y)` — геттер высоты, тоже метод CMap: `FUN_00592f10(x >> 3, y >> 3)`,
т.е. **логические координаты сетки 8×8 = мировые координаты, делённые на 8**.

Добавленные в `ghidra_funcs.tsv` как `CMap` (8 функций):
`0x004093f0` (геттер высоты), `0x00424cc0` (инициализация карты), `0x00590410` (сброс),
`0x00592f10` (аксессор клетки), `0x005939b0` (сброс) + ранее известные `0x00593ec0`,
`0x00594160` (Init), `0x005948b0` (Shut).

**Снятые ошибочные назначения.** Дизассемблирование показало, что `0x00427610`,
`0x00427e30`, `0x005763e0`, `0x00595770`, `0x005e9700` — **не** методы CMap:

| адрес | почему не CMap |
|---|---|
| `0x00427610` | `0x14`/`0x18` не используются; `0x20` читается как байты |
| `0x00427e30` | `0x20` читается как байт-флаг, а не как указатель |
| `0x005763e0` | смещения `0xCAC`/`0xCB5` — другой, гораздо больший объект |
| `0x005e9700` | зовёт аксессор с **глобальной** картой: `FUN_00592f10(PTR_0077241c)`, а не со своим `this` |

**Перепроверено:** `0x00595770` — МЕТОД CMap (звонёт `FUN_00592f10(this)`,
читает `this->x0_8/x1_8/y0_8/y1_8` и `cell->sampleFlags[…]`), класс восстановлен.

Критерий проверки — с кем вызывается аксессор: `FUN_00592f10(this)` = метод
карты, `FUN_00592f10(PTR_0077241c)` = посторонний объект, работающий с глобалом.

* `0x004ca080` — построитель ямы: 10 аргументов, работает через глобал `DAT_0077241c` (карта);
* `0x004c9010` — построитель вершин лент: `(char, char, float*, uint*, ushort*, uint*)`.

## 7. Что осталось нерешённым

* Смысл 2-битного «уровня угла» (`значение & 3`) в маске — ненумерованный, не монотонен по высоте.
* Расхождение двух шкал высоты (логические функции отдают «уровень» байта, рендер считает `7.0 + 0.5*v`).
* Семантика выбора зоны в `sm_draw_stone -exlimit`.
