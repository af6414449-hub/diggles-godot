# Гипотеза геометрии PMP

Дата: 2026-11-14

## Наблюдение

Для `gng_023.pmp`:

- первые поля: `4, 4`;
- следующие 16 байт — матрица 4×4, заполненная значением `2`;
- затем идут структурированные little-endian записи, включая `192, 80, 193, 194, 195, 196`;
- в хвосте повторяются packed-поля `0x00090078`.

## Вывод

Первые 16 байт не описывают визуальный силуэт: они однородны и, вероятно, являются типами/флагами клеток. Геометрия или ссылки на сегменты, вероятно, находятся после матрицы.

Связанный набор ресурсов содержит только `.pmp`, `.l2m`, `.ent` и Tcl-шаблоны, но не отдельный файл с именем `gng_023.3db`. Следовательно, `gng_023.pmp` может ссылаться на общие шаблоны/модели, а не на одноимённый mesh.

## Следующее изменение renderer

Не следует пытаться получать форму карты из одной матрицы PMP. Нужно ввести промежуточную модель:

```text
PmpHeader
PmpCellFlags[width * height]
PmpRecords[]
Layer2Mask
EntityPlacements
```

Сначала отобразить `PmpRecords` как отдельные точки/отрезки с координатами, если они декодируются, и только затем строить поверхность.
