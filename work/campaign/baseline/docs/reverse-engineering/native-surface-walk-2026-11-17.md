# Первый проход пол → стена → площадка → обратно

Последующее приращение: [native-surface-dig-2026-11-17.md](native-surface-dig-2026-11-17.md) связало эту ходьбу с исходными настенными ударами и добавило недостающий `vector_fix`. Ниже сохранён срез первого приращения; его ограничение на wall digging и прежний размер пакета относятся к тому срезу.

17.11.2026. В активной Godot multiplayer-сцене работает движение между уровнями по исходным navigation samples. Проверенный путь: `(8,14.5)` нижнего пола → стена → `(24,10.5)` верхней площадки → обратно. Также можно закончить маршрут на стене: гном остаётся в исходной wall-idle анимации. Выбор верхней цели обычным нажатием в режиме «Выбор» проверен. APK и export preset не менялись.

Это продолжение `native-fix-dig-2026-11-17.md`. **Подтверждённые части** — классификация samples, формула глубины стенового положения и кадры анимаций. **Адаптеры** — поиск маршрута, выбор ближайшего sample при нажатии, скорость и расписание клипов. Полный перенос native `action_walk` этим результатом не объявляется.

## Что прочитано в оригинале

`Diggles.exe`, SHA-256 `58a01d3d80670a6042c66a82684397c98e39c503e00a6e2c2c511f338a30ed74`, image base `0x400000`; установленные Tcl, `mann.3db`, `multi_start_010.pmp`, `BlockDB2.BDB`. Восемь byte-spans с дизассемблированием, Tcl-хеши и четыре независимых BDB fixtures сохранены в соседнем JSON. `tools/audit_native_walk.py --check` повторяет чтение установки и сравнивает доказательство.

| Участок | Правило |
| --- | --- |
| `0x407430`, особенно `0x407496–0x40751D` | Walk-action создаёт контроллер размером 0x7F8 и передаёт параметры в `0x420840`. Это единое действие, а не отдельная Tcl-команда лазания. |
| `0x420F30–0x420F5D` | `-canclimb` записывается в byte +0x7B0. Tcl `z_dignwalk.tcl:607–617,830–843` запрещает лазание для переноса ящика. |
| `0x423730`, ключевой участок `0x423788–0x4237BB` | Если разрешены объекты, bit2=4 и найдена подходящая ladder-сущность, mode=1. Иначе bit1=2 даёт mode=2 (пол), отсутствие bit1 — mode=0 (стена). Валидность path sample проверяется отдельно; mode helper сам не доказывает проходимость. |
| `0x4163A0` | Meta-walk группирует последовательные samples одного режима; canclimb=0 отвергает стеновой участок. Для лестницы учитывается также идентичность объекта. |
| `0x4238E0–0x423A80` | Wall depth = `H(x,y−1)+1`. Только если H ровно 15: `min(H(x−1,y−1),H(x+1,y−1),H(x,y−2),H(x,y))+1`. Без придуманного clamp до 14.5. |
| `0x41A375–0x41A46B`, `0x423BE0` | Промежуточные XY берутся из path sample /8; floor Z при отрицательном X delta равен 12.5, иначе 14.5. Последний target имеет отдельную ветку и сохраняет target XYZ; её нормализация пока не перенесена целиком. |
| `0x68D8A0` | `get_gnomeposition` отдельно проверяет floor bit в округлённой позиции Y+1,Y,Y−1. Это не то же самое, что классификация одного waypoint. Его x87 округление/полный вызов пока не портирован. |

`0x4158A0` вызывает обычный `CMapPathfinder::Calc1` через `0x59D440/0x59D640`; отдельная random-ветка идёт в `0x5A22F0`. Наличие этих вызовов не даёт права назвать наш BFS исходным алгоритмом. Native Calc1 использует дополнительные cell summaries, owner-dependent проверки, ускоренные участки и обработку endpoints — они требуют отдельного переноса.

Source BDB fixtures: `(172,108)`, `(172,96)`, `(171,112)` дают wall Z=12 при H выше=11; `(163,17)` имеет H выше=15, cross heights 15/12/15/15 → Z=13. Последний пример проверяет формулу высоты и сам по себе не объявляется доступной точкой маршрута.

## Реализация в Godot

- `native_walk_pose.gd` — чистые mode/wall-depth/intermediate-floor-depth правила. Неизвестный обязательный BDB probe остаётся неизвестным.
- `surface_walk_action.gd` — отдельное действие актёра. Host BFS обходит **известные** bit0 samples соседями +X,−Y,−X,+Y. Это собственный порядок и стоимость рёбер, не Calc1. При canclimb=0 допускаются только floor samples. Ladder/object samples явно отклоняются.
- `multiplayer_test.gd` выбирает surface-действие для другой высоты либо актёра, уже находящегося на стене. Нижний X/Z floor adapter сохраняется для прежней ходьбы/копания. Прямой команды из wall pose к нижнему полу хватает для нового surface route; возврата через присваивание фиксированного Y нет.
- Исходная глубина пересчитывается по текущим BDB heights для стенового waypoint. Перед шагом проверяются текущие flags/mode. Unknown/утративший доступность sample прерывает только свой маршрут. Замена маршрута сначала планируется; отказ canclimb=0 не уничтожает прежнее действие.
- Вход на стену использует `stand_zu_kletterstand`, выход `kletterstand_zu_stand`. Направления — `kletter_hoch/runter/links/rechts_loop`, быстрый набор — соответствующие `*_schnell`. Wall idle — `kletterstand_anim`; положение сохраняется при отмене.

`tools/export_dwarf_surface_walk.py` экспортирует **12 исходных последовательностей / 152 кадровые ссылки** тела `mann`. Используется прежний mesh decoder; текстуры повторно не копируются. JSON 7 380 027 bytes, SHA-256 `0f8b24b741e7c871a105d97918463d539e6c91d61b3e72437ba2d1dee4f9bc26`. Runtime создаёт meshes/Nodes только при первом использовании конкретного клипа конкретным актёром; mesh cache общий. Начальный smoke node_count остаётся 2504.

Скорость прежнего adapter 0.98 и 12 FPS перенесены как явная временная политика, не извлечённые native значения. Во время transition-клипа позиция удерживается; затем идёт движение с ограничением длины шага. Root motion, native скорость/переходный scheduler и устранение мелких ступенек native smoothing не восстановлены. Направление пола использует исходное правило промежуточной lane, включая текущую host-политику для конечной точки; полная native target-normalization остаётся отдельной задачей.

## Проверено

Godot 4.7.2 headless: **44 assertions**, по одному запуску для `authored_2p` и `authored_4p`. Каждый маршрут туда/обратно содержит 161 sample. Подтверждены два уровня, подъём/спуск, исходные переходные клипы, wall idle, отмена без смены положения, обычное нажатие на верхнюю площадку, запрет canclimb=0 и сохранение другого актёра при unknown sample. Максимальный шаг ограничен `speed*delta`; terrain revision остаётся 0, BDB facts и marks неизменны.

Это проход **по исходному существующему маршруту**, а не уже законченный цикл «новый выкопанный уровень → движение по нему». Копание с wall pose пока отклоняется: старый executor поддерживает только нижний пол и ground-клипы.

OpenGL: **47 assertions**, дополнительно сохранены `wall_up.png`, `upper_platform.png`, `wall_idle.png`, три общих ракурса и `scene_space.json` в `native-surface-walk-2026-11-17/`. Крупные планы подъёма, площадки и wall idle просмотрены. JSON содержит историю surface actions, planner, clips, result и итоговую позу актёров.

Повторные проверки: очередь копания 37 (четыре callback/мутации), worker 195, независимые актёры 21, жесты 37. Exporter `--check` и source audit `--check` прошли; lint 37 scripts — 0 ошибок/предупреждений. Smoke всех трёх сцен — 0 ошибок/предупреждений. Это desktop GL Compatibility; Android GPU не измерялся.

## Как проверить вручную

Открыть `godot/scenes/multiplayer_test.tscn`, запустить, выбрать гнома инструментом «Выбор» и нажать на верхнюю каменную площадку справа от центральной стены. Затем выбрать нижний пол для обратного маршрута. Нажатие на доступную стену позволяет закончить маршрут на ней. Сетка `--show-native-walkmap` остаётся необязательной диагностикой.

```powershell
python -B tools/audit_native_walk.py --check
python -B tools/export_dwarf_surface_walk.py --check
& 'C:/Users/frant/OneDrive/Рабочий стол/godot/Godot_v4.7.2-stable_win64_console.exe' --headless --path godot --debug --ignore-error-breaks --script res://tools/native_surface_walk_self_test.gd
```

Следующая работа: исходная нормализация target, путь от `vector_fixdig` до walk endpoint, Calc1/owner summaries и object overlays. Затем связать копание с новым surface action и пройти по реально изменённому уровню; после доказанного ladder footprint — лестница. Женские клипы известны по прежнему аудиту, но этот runtime-пакет ограничен тремя текущими мужскими тестовыми актёрами.
