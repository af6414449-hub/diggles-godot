### 1. Геометрия: **квад на клетку**, UV — локальные координаты клетки

**ФАКТ (Diggles.exe):** земля строится **по одной клетке**, отдельным мешем на каждую клетку.
- `FUN_004c8480_004c8480.c:45,245-253` — на каждую клетку вызывается `FUN_004ca830(x, y)`, возвращающая запись 0x1C Б с тремя слотами текстур (`+8`, `+0xC`, `+0x10`).
- `FUN_004ca080_004ca080.c:299-336` — вершины клетки пишутся в **собственный буфер** (`local_18 + 0x1378`, предел 0x400 = 1024 вершины) и отправляются одним вызовом `FUN_0045fd00(0x2c2, …)`. Никакого «общего полигона на карту» в коде нет.

**ФАКТ (Diggles.exe):** позиции вершин **и** UV берутся из **глобальной таблицы вершин BlockDB**; запись = **20 Б = 5 × float32 (x, y, z, u, v)**.
- `CMap__Init_00594160.c:117-141` — загрузка `data\BlockDB0.BDB` / `BlockDB1.BDB` / `BlockDB2.BDB` (выбор по `DAT_0076838c`) → `FUN_00565ab0`.
- `FUN_00565ab0_00565ab0.c:82-83` — `DAT_00b836a8` = число вершин, `DAT_00b836a4` = база таблицы; `:178-188` — таблица вершин лежит **в хвосте файла `.BDB`**, её смещение вычисляется из заголовка и размеров трёх массивов.
- `FUN_00462b40_00462b40.c:17-18` — чтение записи; `:24-26` — позиция (x, y, z); `:41-42` — U; `:58-61` — V.
- U/V дополнительно «вжимаются» к центру: `u' = (u − 0.5) × 0.984375 + 0.5` (то есть 63/64 отклонения), `FUN_00462b40.c:41,58`. Второй UV-набор = **копия первого** (`:42-43` → `[7] = [5]`, `:59-60` → `[8] = [6]`).

**ФАКТ (Diggles.exe):** при сборке квада двигаются **только X и Y клетки**; UV остаются шаблонными.
- `FUN_004ca080_004ca080.c:308-333` — `*pfVar13 += fVar14` (X += X клетки), `pfVar13[1] += (float)piVar3` (Y += Y клетки), `pfVar13[7] = pfVar13[5]`, `pfVar13[8] = pfVar13[6]`. Ни одного обращения к UV по мировой позиции в функции нет.
- Шаблон вершины выбирается по **ID блока высот** клетки: `FUN_004ca080.c:52-60` — `*(int *)(DAT_0077241c + 0x24) + cell[0x00] * 0xC`, т.е. одна и та же запись BlockDB на все клетки с одинаковым блоком.

**Эмпирика по данным игры** (скрипт `work/campaign/caves-decomp/z35_bdb_uv.py`, читает `data/BlockDB{0,1,2}.BDB` по формуле `FUN_00565ab0`):

| файл | вершин | X | Y | Z | U | V |
|---|---|---|---|---|---|---|
| `BlockDB0.BDB` | 1411 | 0…1 | 0…1 | 7.0…14.5 | 0…7.5 | 0…7.5 |
| `BlockDB1.BDB` | 2504 | 0…1 | 0…1 | 7.0…14.5 | 0…7.5 | 0…7.5 |
| `BlockDB2.BDB` | 3323 | 0…1 | 0…1 | 7.0…14.5 | 0…7.5 | 0…7.5 |

- **X, Y ∈ [0,1]** ⇒ вершина лежит **внутри своей клетки**.
- **Z ∈ [7.0, 14.5]** ⇒ мировая высота = 7.0 + 0.5·уровень (совпадает с З8/З13).
- У **плоского** блока (уровень 15, первые 9 записей) UV = позиция: (0,0), (1,0), (0,1), (1,1), (0.5,0), (0,0.5), (0.5,0.5), (0.5,1), (1,0.5) — **сетка 3×3 внутри клетки**, `u = x`, `v = y`.
- Тайлинг UV > 1 встречается только у блоков с перепадом высот (максимум 7.5 на одной клетке).

**⇒ ОТВЕТ НА ВОПРОС 1: квад на клетку, UV в пределах клетки (0…1).** Текстура земли повторяется **по клеткам**, а не натягивается на мировые координаты. «Большого полигона с UV от позиции» в движке нет.

**ФАКТ (Diggles.exe):** формат вершины земли — **UL2CS (0x2C2 = 36 Б)**:
`POSITION (3 × f32)` + `COLOR0 (u32, ARGB)` + `COLOR1 (u32, ARGB)` + `TEXCOORD0 (2 × f32)` + `TEXCOORD1 (2 × f32)`.
- `FUN_004ca080.c:199-222` — цвет пишет `FUN_004cc040` (запечённый свет), `:335-336` — отправка в рендер с флагом формата `0x2C2`.
- Второй UV-набор дублирует первый ⇒ движок не различает «основной» и «детальный» UV в вершине; различие делает сам шейдер (З31).

**ФАКТ (Diggles.exe):** при сшивке соседних клеток UV «переворачиваются», но остаются в 0…1.
- `FUN_004c9010_004c9010.c:61-94` и `:547-581` — если угол клетки не совпадает, у вершины меняются местами X/Y, а `y → 1 − y`. То есть UV «отражаются» по границам блоков, но не становятся мировыми.

### 2. Структура клетки и три поля, которые всё определяют

**ФАКТ (Diggles.exe):** клетка = **0x7C Б**; `FUN_00592f10_00592f10.c:23-25` (`iVar2 * 0x7C + map->0x14`).
**ФАКТ (Diggles.exe):** координаты клетки **клампятся** к границам карты — `FUN_00592f10.c:9-21` (`x` зажимается в `[map+0x84, map+0x8C-1]`, `y` — в `[map+0x88, map+0x90-1]`). ⇒ «клетка вне главы» — это **реальная клетка у края карты**, а не пустое место; за её пределами геометрии нет.

**ФАКТ (Diggles.exe):** `cell+0x14` (uint16) — **вариант | группа | 4 кода углов**:

| биты | смысл |
|---|---|
| 0…4 | номер варианта (0…31) |
| 5…7 | **группа** (0…7) |
| 8…9 | код угла 0 |
| 10…11 | код угла 1 |
| 12…13 | код угла 2 |
| 14…15 | код угла 3 |

Подтверждено **двумя независимыми** путями:
1. `FUN_004c4c50_004c4c50.c:17` — `uVar1 = param_1 >> ((iVar3 + 8) & 0x1F) & 3` при `iVar3 = 0,2,4,6` ⇒ углы в битах 8…15 по 2 бита; `:29-33` — построение маски; `:55` — `группа = (param_1 >> 5) & 7`; `:66` — `вариант = (param_1 & 0x1F) % count`.
2. `FUN_00532a70_00532a70.c:138-172` — **запись** этих битов: `((param_1 & 0xFFFF) << 9 | group) << 5 | old & 0x3F00` ⇒ код угла 3 → биты 14…15; `<< 3` ⇒ угол 0 → 8…9; `<< 5` ⇒ угол 1 → 10…11; `<< 7` ⇒ угол 2 → 12…13; `:129-131` — вариант в биты 0…4 (`& 0xFFE0` | `v & 0x1F`); `:140-142,150-152,158-160,166-168` — группа наследуется от соседней клетки, если новый код не задан.

**ФАКТ (Diggles.exe):** код угла: `0` — «как у базового уровня», `1` — «поднят», `2` — «база = 1» (`FUN_004c4c50.c:18-25, 87-88`).

**ФАКТ (Diggles.exe):** `cell+0x18` (uint16) — **материал**: младшие 2 бита = тип (0 = камень, 2 = земля, 3 = «клетки нет»), биты 8…15 = **байт вариации**.
- генератор карты: `FUN_00598f10_00598f10.c:149` — `*(ushort *)(cell + 0x18) = (случайное & 0xFF) << 8 | 2`;
- загрузчик `.pmp`: `FUN_005992b0_005992b0.c:335-339` (`| 3` — «каменная полоса»), `:373`;
- чтение — **у соседних** клеток (4 угла): `FUN_004ca830_004ca830.c:169-171, 206-208, 242-244`.

### 3. Два слоя текстуры земли и как они выбираются

**ФАКТ (Diggles.exe):** у клетки земли **два слоя текстур**.

*Слой 1 (база, «Gnd»)* — `Gnd_<A|B|C><01…15>` + маска перепада `Msk_<4 буквы A/B>01`:
- `FUN_004cd9d0_004cd9d0.c:62-68` — `"ground/Gnd_%c%c%c.tga"`, где буква = код угла + `'A'` (0/1/2 → A/B/C), а число = 01…15 (`(n+1)/10` и `(n+1)%10` двумя цифрами);

*Слой 2 (scape)* — `urw_/swf_/kris_/lava_/urw2_/swf2_/kris2_/lava2_` + `XXXX`, где XXXX — **4 двоичные цифры = маска поднятых углов 0…15**; в игре **160 файлов** в `data/Ground/detail/`.

**ФАКТ (Diggles.exe):** слой 2 подключается **Tcl-командой** `load_scape_texture <группа> <слой 0/1> { 16 списков }`:

### 4. Роль материала: **в группу/слой/маску он не входит**

**ФАКТ (Diggles.exe):** `FUN_004c4c50` (выбор текстуры слоя 2) принимает **только** `cell[0x14]`; `cell+0x18` в этой функции **не читается ни разу** (`FUN_004c4c50.c:2, 17, 29, 55, 66` — единственные чтения `param_1`).

**ФАКТ (Diggles.exe):** материал участвует в выборе **слота** (81 комбинация) и **номера варианта** — но не в выборе семейства:
- `FUN_004c4ae0_004c4ae0.c:49-50` — индекс слота = комбинация **младших 2 бит материала** четырёх соседних клеток: `((((p5&3)*3 + (p4&3))*3 + (p3&3))*3 + (p2&3))` ⇒ 81 комбинация (значение 3 = «клетки нет»); заполняются в `FUN_004cde30_004cde30.c:79-112` перебором 3×3×3×3;
- `FUN_004c4ae0.c:41-47` — из слова материала берётся **старший байт**: `uVar3 = param_2 & 0xFFFFFF00`; `:71` — `base + ((комбо | uVar3) >> 8) % count` ⇒ **материал выбирает один из вариантов `_a…_f` в том же слоте**;
- `FUN_004c4ae0.c:45-47` — при `param_9 != 0` рандомизация выключается (`uVar3 = 0`); вызов: `FUN_004ca830_004ca830.c:333-341` — `param_9 = (block[0x54] & 0xF) < 11.0` ⇒ **на склонах (уровень < 11) вариант фиксирован, на равнинах (уровень ≥ 11) — рандомизируется материалом**.

**ФАКТ (Diggles.exe):** выбор текстуры слоя 1 (81-комбинации `Gnd_*`) идёт через `FUN_004c4ae0` и `FUN_004cd020`/`FUN_004cd9d0` — то есть база тоже зависит от комбинации материалов четырёх соседей, но **не** от «группы уровня».

**⇒ ОТВЕТ НА ВОПРОС 2: ПОДТВЕРЖДЕНО.** Материал клетки **не** определяет семейство/группу текстуры земли — он определяет только (а) слот по комбинации материалов четырёх соседей и (б) номер варианта внутри слота. Семейство (`urw_`/`swf_`/`kris_`/`lava_`) задаётся **группой из `cell[0x14]`, а группа — уровнем/скриптом**, а не материалом.

### 5. «Плоская земля» и нейтральная деталь: **подтверждено**

**ФАКТ (игра):** ровно **2 из 160** детальных текстур полностью одноцветны (проверено попиксельно, скрипт `z35_bdb_uv.py`):

| файл | размер | цвет пикселя (RGBA) |
|---|---|---|
| `data/Ground/detail/50PGray.tga` | 1×1, 32 бита | `80 80 80 00` |
| `data/Ground/detail/urw_0000.tga` | 64×64, 32 бита | `80 80 80 00` во всех 16 384 байтах |

То есть **`urw_0000.tga` — полностью прозрачный нейтральный серый**, а не «текстура земли с узором». Все остальные 158 детальных текстур — разноцветные.

**ФАКТ (Diggles.exe):** fallback-текстура земли = **`data/ground/detail/50PGray.tga`**:
- `FUN_004cde30_004cde30.c:28-49` — строка собирается из литерала exe по VA `0x7248E4` = `"data/ground/detail/50PGray.tga"` (префикс `0x724904` = `"data/ground/detail/"`);
- `FUN_004c4c50.c:79-84` — используется, когда слот пуст **или все углы равны** (маска 0), и ставится **режим (техника) 0x12**;
- **но** в поставляемой игре слот маски 0 непуст (`urw_0000.tga`, `txtinit.tcl:42`) ⇒ на реальной земле 50PGray не показывается, а показывается `urw_0000.tga` — **то же самое по пикселям**, просто 64×64 вместо 1×1.

**⇒ ОТВЕТ НА ВОПРОС 3: ПОДТВЕРЖДЕНО, с важным уточнением.**
- Плоская клетка (все 4 угла одной высоты) ⇒ маска 0 ⇒ деталь **`urw_0000.tga`**.
- Она **действительно нейтральная**: все пиксели = RGBA(0x80, 0x80, 0x80, 0x00) ⇒ вклад в цвет = нулевой.
- Она **общая для всех семейств**: `txtinit.tcl` прописывает ровно этот файл в слот маски 0 для групп 0 (Urwald), 1 (Schwefel), 2 (Kristall) и 3 (Lava) — поэтому «*_0000» в других семействах (swf/kris/lava/urw2/swf2/kris2/lava2) **не существует**, и он и не нужен.
- `50PGray.tga` — та же картинка в 1 пиксель, используется как **заглушка** на случай пустого слота.

### 6. Что это меняет для порта

1. **Рельеф — это сетка квадов по клеткам, UV = (x, y) клетки.** Не «большой полигон с мировыми UV» и не «текстура на весь мир». Тайлинг по клеткам даёт характерную «сетку» на траве.
2. **Формат вершины земли — UL2CS (36 Б)**: `POS(3f) + COLOR0(u32) + COLOR1(u32) + UV0(2f) + UV1(2f)`. Второй UV = копия первого; **свет запечён в COLOR0/COLOR1**, realtime-свет земле не нужен.
3. **Геометрия земли берётся из `BlockDB*.BDB`, а не генерируется**: таблица вершин (x, y, z, u, v) в хвосте файла, вершины внутри клетки (X, Y ∈ [0,1]), Z = 7.0 + 0.5·уровень. Меш на клетку = шаблон блока + сдвиг на (X, Y) клетки.
4. **Текстуры земли — два слоя, оба выбираются по данным клетки, а не «по одному материалу»**:
   - слой 1: `Gnd_<A|B|C><01…15>` (+ маска `Msk_*01`), слот = комбинация материалов 4 соседей (81 шт.);
   - слой 2: `urw_/swf_/kris_/lava_*` (+ `_a…_f`), слот = (группа, слой 0/1, маска углов), группа = `cell[0x14] >> 5 & 7`.
   Вся раскладка слоя 2 вынесена в **Tcl** (`load_scape_texture`) — её нужно перенести как данные, а не как код.
5. **Ключ выбора = `cell+0x14`**: вариант (биты 0-4) | группа (5-7) | коды 4 углов (8-15). Если порт читает свой формат записи, эти три поля надо разложить именно так.
6. **Свободная земля (вне главы)**: `cell+0x14] = 0` ⇒ группа 0, слой 0, маска 0 ⇒ деталь `urw_0000.tga` (нейтральная). То есть **вся плоская свободная земля карты в оригинале — одна и та же нейтральная текстура**, и вид ей задаёт второй слой (`Gnd_*`) и освещение вершины. Если порт рисует на этой земле «красивую» текстуру — это расхождение с оригиналом; если порт рисует пусто — тоже.
7. **Клетки клампятся по краям карты** (`FUN_00592f10.c:9-21`) ⇒ «край карты» не обрезан, а повторяет крайнюю клетку.

### 7. Что осталось неизвестным и как проверить

1. **Кто пишет `cell+0x14` для клеток главы** (маска поднятых углов) — найден только писатель `FUN_00532a70` (штамп объектов/углов, `+0x14` на 4 соседних клетках); не разобрано, кто пишет его для «штатной» главы. **Проверка:** поставить брейкпоинт на `FUN_004c4c50` и посмотреть стек вызова для клетки главы.
2. **Значение `cell+0x1C` (байт 28)** — в коде читается как «байт вариации» (`FUN_004ca830.c:170, 207, 243`, сдвиг << 8) и используется для затемнения углов (`FUN_004c8480.c:62-211`); внятной семантики нет. **Проверка:** сопоставить с байтом 28 записи порта (0x02 / 0x00 / 0x80 / 0x83) и выяснить, это «тип породы» или «флаги».
3. **Точный смысл битов 8…15 `cell+0x14]` при коде угла 3** — код 3 в `FUN_004c4c50.c:17-25` трактуется как «продолжать сканировать», но нигде не пишется. **Проверка:** найти писателя, который может дать 3.
4. **Значение «режима» 0x12** (ставится, когда все углы равны) — это id техники из реестра З31? **Проверка:** сопоставить 0x12 = 18 с таблицей `z31_shaders.tsv` и с `scape_*` именами.
5. **Семейство текстур, реально применяемое на конкретном уровне**: индекс 0…3 ставится по подстроке имени уровня (`FUN_00583080.c:38-78`), но `load_scape_texture` описывает группы 0,1,2,3,6 — группы 4,5,7 в `txtinit.tcl` **не заданы**. **Проверка:** найти, кто ещё вызывает `load_scape_texture` (возможно, другой .tcl), и как выбирается группа 6 (Kristall Layer2).
