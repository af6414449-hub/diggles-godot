# З31. Как объект выбирает технику: полная цепочка «объект → группа → техника → состояние рендера»

*(2026-11-22; разобрана цепочка выбора материала/техники и полностью извлечены таблицы шейдеров)*

Закрывает блокеры «кто заполняет 16-элементную таблицу техник для типа» и
«семантика полей записи техники». Это ровно тот слой, из-за которого порт
«применяет не те текстуры»: выбор техники — это не эвристика, а три таблицы,
которые теперь извлечены дословно.

## 1. ФАКТ (Diggles.exe): реестр шейдеров — это три параллельных массива в менеджере рендера

Менеджер (`DAT_0076a2ec`, создаётся в `FUN_005ade30_005ade30.c:19-68`) хранит
три реестра подряд, и у каждого — свой массив и свой счётчик:

| что | база массива | счётчик | размер записи | регистрация |
|---|---|---|---|---|
| текстапы (textstage) | `+0x48` | `+0x4C` | 0x50 | `FUN_0045a850` |
| шейдеры (shader) | `+0x850` | `+0x854` | 0x6C | `FUN_0045aa00` |
| материалы (material) | `+0x1058` | `+0x105C` | 0x48 | `FUN_0045ac70` |

Evidence: `FUN_0045dd40_0045dd40.c:63,71` (textstage, шаг 0x50),
`FUN_0045dd40_0045dd40.c:103,111` (shader, шаг 0x6C),
`FUN_0045dd40_0045dd40.c:143,151` (material, шаг 0x48).

### 1.1 Запись шейдера (0x6C байт)

```
+0x00..+0x40   17 числовых dword  (индексы 0..16)
+0x44..+0x63    8 числовых dword  (индексы 17..24)
+0x64          указатель на имя шейдера (refcounted string)
+0x68          указатель на имя родителя
```

Запись материала (0x48 байт):
```
+0x00..+0x3C   16 dword — id техник по слотам 0..15
+0x40          имя материала (group)
+0x44          имя родителя
```

### 1.2 Наследование: каждая техника — копия `default`

ФАКТ: запись `default` (id 0) — это шаблон; любой другой шейдер создаётся
как её копия и затем переопределяет нужные поля.

* `FUN_00455ad0_00455ad0.c:23` → `FUN_004559a0(record, base)` копирует
  `base[0]` (то есть запись 0) в создаваемую запись; поля +0x64/+0x68
  переносятся как строки.
* `FUN_00455ad0_00455ad0.c` (дизасм. `0x455B14–0x455B5D`): `+0x68` новой
  записи получает имя из `+0x64` шаблона ⇒ **родитель всех шейдеров, кроме
  `default`, = `default`**.
* Значения по умолчанию — конструктор `FUN_00455760_00455760.c:38-67`:

```
+0x00 = 1   +0x04 = 1   +0x08 = 4   +0x0C = 0   +0x10 = 0
+0x14 = 8   +0x18 = 0   +0x1C = 2   +0x20 = 1   +0x24 = 0
+0x28 = 3   +0x2C = 1   +0x30 = 0   +0x34 = 0   +0x38 = 0xFFFFFF
+0x3C = 0   +0x40 = 0   +0x44 = 1   +0x48..+0x60 = 0
+0x64 = "default"   +0x68 = "disable"
```

Тот же конструктор ставит `+0x68 = "disable"` — то есть сам `default`
наследует несуществующий «disable».

## 3. ФАКТ (Diggles.exe): полная цепочка выбора техники при отрисовке

Шаг 1 — **объект знает номер группы и номер слота**.
`FUN_00483d80_00483d80.c:252-259`:

```
uVar15 = local_30[2];                                  // индекс группы материала
piVar9 = material_array + uVar15 * 0x48;              // запись группы
piVar9 = piVar9 + *puVar3;                             // + слот 0..15
iVar8  = *piVar9;                                      // id техники
```

Шаг 2 — **подстановки «недоступной» техники** (`FUN_00483d80_00483d80.c:264-276`):

| id из таблицы | подставляется | техника |
|---:|---:|---|
| 7 | 6 | `model_solid` → `model_blend` |
| 18 | 19 | `scape_solid` → `scape_blend` |
| 33 | 7 | `alpha_light` → `model_solid` |
| иначе | без изменений | (в т.ч. 0x21 = 33 → 7) |

Шаг 3 — **результат кладётся в состояние отрисовки**: `local_14[4] = iVar5`
(в 8 функциях применения это `param_1[4]`).

Шаг 4 — **состояние отрисовки каждого объекта** (`FUN_004899b0_004899b0.c:280-292`,
однотипно во всех 8 функциях):

## 8. Что это меняет для порта (Godot)

1. **Выбор материала — это таблица, а не эвристика.** В порту нужно
   реализовать ровно три структуры: 37 техник с 25 параметрами, 16-слотовую
   таблицу на группу и подстановки 7→6 / 18→19 / 33→7. Любая эвристика
   («выберем blend, потому что объект полупрозрачный») даст не те текстуры.
2. **Наследование от `default`** — в Godot это material resource с
   `shader_parameter`-наследованием; параметры `default` (см. п. 1.2) —
   это базовые значения всех 36 остальных техник, а не нули. Типичная ошибка
   ИИ-порта — взять нули вместо значений по умолчанию.
3. **Поля, которые читает движок, а не порт:**
   `+0x04` (**ZWriteEnable**; 0 ⇒ другая ветка вывода во всех 8 функциях
   применения техники — см. З36),
   `+0x0C` (**AlphaEnable**; 0 ⇒ «настоящего шейдера нет», влияет на ключ
   сортировки),
   `+0x20` (**DestBlendMode**; ≠ 1 (ZERO) ⇒ непрозрачный ⇒ особый порядок
   отрисовки — см. З36),
   `+0x30/+0x34/+0x38/+0x3C` (доп. параметры техники, читаются
   `FUN_004860c0`; сейчас ненулевые только у glow-техник: `+0x30 = 1`,
   `+0x34 = 50`).
4. **`+0x38 = 0xFFFFFF`** — базовый цвет (белый) ⇒ переносится в
   `albedo_color`/`modulate`, а не в отдельный шейдер.
5. **Формат вершин выбирается функцией отрисовки, а не материалом:**
   6 из 8 путей используют UL1CS (0x1C2, один набор текстурных координат),
   2 пути — UL2CS (0x2C2, два набора). Смешивать их в одном меше нельзя.
6. **Группы материалов — именованные и переключаемые из Tcl**
   (`default` / `additiveonly` / `modelnozwrite` + пользовательские).
   В Godot это должен быть ресурс-«variant» с именем, а не зашитое
   соответствие по типу объекта.
