## 1. Полное правило `FUN_005a6b40` (0x5a6b40)

Вход — прямоугольник валидатора **в суб-клеточных координатах**.

1. **Рабочая область** (`:50-74`):
   `x ∈ [max(x0, mapX0+24), min(x1, mapX1−24))`, `y ∈ [max(y0, mapY0+16), min(y1, mapY1−24))`,
   где `mapX0/mapX1/mapY0/mapY1` — границы карты **в суб-клетках** (`map+0x94…0xa0`).
   Отступы: 3 клетки слева/справа, 2 клетки снизу, 3 клетки сверху.
2. **Сетка высот** (`:71-78` → `FUN_00595e40`, 0x595e40): карта 8×8 уровней блоков по **расширенному** прямоугольнику
   `x0−8 … x1+8`, `y0−16 … y1+2` (суб-клетки). Клетки вне карты **зажимаются** к её краю (`FUN_00595e40.c:40-63`).
   Значение = **уровень** (0..15), `world-Z = 7.0 + 0.5·v`.
3. **Фильтр 1** (`:104-108`): бит 7 байта `cell+0x18` → состояние **0**.
4. **Фильтр 2** — 31 проверка соседей (`:111-388`): если хоть один из 31 смещения имеет уровень **≥ 14** → состояние **0**.
   Смещения (Δстрока, Δстолбец) **в суб-клетках**, все в сторону меньшего Y:
   `(−1,0)`, `(−2,±2)`, `(−3,±4)`, `(−4,0)`, `(−5,0)`, `(−5,±5)`, `(−5,±7)`, `(−6,±2)`,
   `(−8,0)`, `(−8,±4)`, `(−8,±7)`, `(−10,±2)`, `(−11,±5)`, `(−12,0)`, `(−12,±7)`,
   `(−13,±3)`, `(−15,0)`, `(−15,±4)`, `(−15,±7)`.
5. **Фильтр 3 — «ступенька»** (`:414-469`), **две ветви**:
   * `h[r−1][c] + 2 < h[r][c]` **И** `h[r−8][c] + 2 < h[r][c]` → состояние **3**;
   * иначе `h[r][c] + 2 < h[r+1][c]` **И** `h[r−15][c] + 2 < h[r+1][c]` → состояние **3**.
   Порог «+2» = разница **≥ 3 уровней** (1.5 world-Z).
6. **Иначе состояние 1** (`:414`), запись по одному байту на суб-клетку (`:503-512`), слив в `cell+0x3c` (`:518`).

Итоговая формула:

```
состояние = 0, если (cell+0x18) & 0x80
          = 0, если любой из 31 соседей имеет уровень >= 14
          = 3, если (h[r-1]+2 < h[r] и h[r-8]+2 < h[r]) или (h[r]+2 < h[r+1] и h[r-15]+2 < h[r+1])
          = 1 иначе
```

## 2. Формат RLE-секции `.pmp` — важное уточнение раскладки

RLE декодируется в **плоское изображение (W·8)×(H·8) суб-клеток** (64·W·H байт), а **не** как 64 байта подряд на клетку:

```
индекс суб-клетки (x,y) плоской карты = y*(W*8) + x
```

`FUN_00596550_00596550.c:70, 121-124` — источник читается как `((row8 − y0) * (x1 − x0)) + (col8 − x0)`, т.е. построчно с шагом W·8.

**64 байта одной клетки в RLE НЕ идут подряд** — они разнесены по изображению с шагом W·8.
(В `cell+0x3c` — наоборот, 64 байта клетки идут подряд; это разные раскладки.)

**Контрольный тест «контекст = карта главы»** (сетка высот строится по всем 15 709 клеткам главы из `native_campaign_chapter.json` → BDB, а не по клеткам шаблона) даёт **93.77 %** — заметно хуже.

⇒ **Гипотеза «RLE-карта `.pmp` помечает ступеньку по контексту карты» — ОПРОВЕРГНУТА.**
Карта считается beautifier'ом **по самому шаблону**: его собственные клетки, а за границей шаблона — клетки шаблона, зажатые к его краю (как `FUN_00595e40` зажимает клетки к границам карты).
В шаблоне главы это работает и для больших шаблонов (60×36, 80×48) — 100 %.

## 4. Отметка «3» и однородность карты 8×8 блока (пересчёт таблицы инициатора)

По всем 15 709 клеткам главы (RLE разложен с правильным шагом W·8):

| карта 8×8 блока однородна | есть отметка «3» | есть «земля» (1 или 3) | клеток |
|---|---|---|---|
| нет | нет | нет | 3 308 |
| нет | нет | **да** | 394 |
| нет | **да** | да | **869** |
| да | нет | нет | 10 772 |
| да | нет | да | 364 |
| да | **да** | да | **2** |

⇒ Отметка «ступенька» в 869 случаях из 871 приходится на клетку с **неоднородной** картой 8×8;
однородных клеток с отметкой «3» — **всего 2 из 15 709** (0.013 %).

**Пример из §11.6 отчёта инициатора (блок 80, клетка главы (163,94)) разобран отдельно**
(`z16_block80.py`): клетка относится к шаблону `hol_raetsel_001.pmp` (размещение (148,76), локальная клетка (15,18)).
Собственная карта 8×8 блока 80 однородна (уровень 11 ⇒ world-Z 12.5), и **RLE-карта этой клетки = все нули**
(ни «земли», ни «ступеньки») — блок 80 = камень, пола нет.
Ошибка наблюдения — в раскладке RLE: при отсчёте 64 байт «подряд на клетку» (шаг 1) вместо шага W·8
суб-клетки клетки выбираются из произвольного места карты.

Скрипты: `z16_step_table.py`, `z16_block80.py`.

## Что это меняет для порта

* **RLE-карта `.pmp` — это результат beautifier'а, и формула теперь известна точно.**
  Порт может и взять её из файла (проще, надёжнее, уже сделано), и воспроизвести из BDB.
* **Если воспроизводить — нужны:** карта ID блоков (`.pmp` или экспорт главы) → карты 8×8 из BDB → формула п.1.
  Контекст = клетки **самого шаблона** с зажатием к краю; карта главы для этого не годится.
* **Раскладка RLE при разборе:** плоское изображение (W·8)×(H·8), шаг W·8 — не 64 байта подряд на клетку.
* Портовым инструментам, которые уже декодируют RLE (инициатор: `tools/audit_pmp_subcell.py`; порт: `tools/export_campaign_chapter.py:56-72` — там RLE **пропускается**), важно проверить шаг.

## Что осталось неизвестным

* **Сценарий записи RLE-карты в `.pmp` в редакторе** — требует проследить путь «выемка → `FUN_005a3fd0` → Service → beautifier → сохранение `.pmp`».
* **Как именно редактор вызывает beautifier** (с каким прямоугольником и флагом) — из кода не восстановлено; измерение показывает, что результат равен прогону beautifier'а по самому шаблону с зажатыми краями.
* **Визуальная проверка в оригинальной игре** не выполнялась (было бы полезно снять `cell+0x3c` в отладчике на живой карте и сравнить с прогоном формулы).
