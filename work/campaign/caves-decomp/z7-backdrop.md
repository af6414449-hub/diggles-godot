## З7.1 Что именно является «задним планом» в кампании

**ФАКТ (Diggles.exe): отдельной сущности «задний план» (небо/пустота вокруг острова) в движке НЕТ.** Сцена рисует ровно две вещи: (а) блочные меши главы (`GetBlock`/`GetBlockHole`) и (б) **плоскую землю карты** — плоские четырёхугольники на Z = 14.5, накрывающие прогоны свободных клеток. За пределами прямоугольника карты не рисуется **ничего**: ни земли, ни неба, ни отдельной плоскости.

Evidence: `CScapeRenderer__RenderScape_004c4de0.c:565-566` и `:573-574` — рендер сцены обходит только клетки внутри прямоугольника карты, с допуском 2 клетки:
```c

        ...
          if (((*(int *)(DAT_0077241c + 0x84) + 2 < iVar4) && (iVar4 < *(int *)(DAT_0077241c + 0x8c) + -2)) && ...
```
(`map->0x84/0x8c` = X-прямоугольник клеток, `map->0x88/0x90` = Y; при `map create 512 640` это [0,512)×[0,640) — см. З3.)

Evidence: `CScapeRenderer__RenderScape_004c4de0.c:613-614` — после обхода клеток вызываются только два «рисователя»: `FUN_004c5e20()` (земля) и `FUN_004c6030()` (стены). Отдельного «неба»/«фона» в коде рендера нет.

**ФАКТ (Diggles.exe): «пустота» вокруг острова в оригинале — это просто чистый цвет кадра.** Никакой плоскости на месте «фона» нет.

## З7.2 Плоская земля карты: координаты и привязка

**ФАКТ (Diggles.exe): плоская земля карты — это плоский четырёхугольник (2 треугольника) на Z = 14.5, покрывающий прямоугольный прогон свободных клеток, с мировыми координатами клеток и зазором 0.02 между соседними прогонами.**

Evidence: `FUN_004cca20_004cca20.c:41-109` — 0x4cca20 — четыре вершины прогона:

## Поправка 2026-11-21 (по разбору сессии стен): плоскость земли = 14.5, а не 15.0

**Что было неверно.** В первой редакции этого документа и в отчёте стояло
«плоскость земли карты на world-Z 15.0 (уровень 16), на 0.5 выше поверхности главы».
Это ошибка разбора float: `0x41680000` = **14.5 ровно**
(`struct.unpack('<f', 0x41680000)` = 14.500000; для 15.0 нужен `0x41700000`).
Плоскость **копланарна** с поверхностью главы (уровень 15).

**Что это меняет.**

1. **Высота совпадает.** Порт кладёт свободную землю на 14.5 (уровень 15) ⇒ по высоте
   порт **совпадает с оригиналом**; править нечего. Прежняя запись «фон на 0.5 ниже
   оригинала» была неверной.
2. **Верх вертикальной грани — тоже 14.5**, а не 15.0 (`FUN_004c6b20:186-241`:
   Z от `local_14` до `0x41680000`). Это меняет правило для порта из З1:
   «грань от уровня клетки до 15.0» ⇒ «**от уровня клетки до 14.5**».
3. **Разница в 0.5 world-Z почти не видна на экране.** Геометрия доски: экранная
   координата `s = y·cosθ − z·sinθ`, где θ — наклон камеры **от нормали доски**
   (θ = 0.29 рад = 16.6°, `Campaign.tcl:10 set_view 246.7 28.8 1.478 -0.29 0.05`).
   * чистый сдвиг от высоты: `Δs = Δz·sinθ` = 0.286·Δz клетки;
   * эквивалентное расстояние **по рядам** (в плоскости карты): `Δy = Δz·tanθ`
     = 0.298·Δz — вдоль луча `ds = 0`, откуда `dy·cosθ = dz·sinθ` ⇒ `dy = dz·tanθ`.
   ⇒ при Δz = 0.5 (15.0 против 14.5): 0.143 клетки по экрану и 0.149 ряда —
   **в пределах погрешности кадра**.
   ⇒ **вопрос «накрывает ли плоскость выработку» — не вопрос высоты, а вопрос того,
   насколько близко к выработке подходят свободные клетки**: перекрытие начинается,
   когда свободная полоса в сторону камеры ≈ `(14.5 − z_выработки)·tan(16.6°)`:
   пол выработки 12.5 ⇒ 2.0·0.298 ≈ **0.6 клетки**; дно породы 7.0 ⇒ 7.5·0.298 ≈ 2.2 клетки.
   Контроль предельных случаев: θ = 0 (камера строго сверху) ⇒ 0 ✓; θ → 90° ⇒ ∞ ✓ —
   то есть именно `tan`, а не `cot`. Прежняя запись «·cot(16.6°) ≈ 6.7 клетки» была
   обратным отношением; исправлено 2026-11-21 по разбору сессии стен.
4. **Разбивка граней главы в исправленном виде** (принято от сессии стен, они пересчитали
   напрямую через `Walls.border_quads()` / `cliff_quads()`, golden-значения в self-тесте):
   **162 грани границ + 1288 уступов + 106 плоских = 1556.**
   Прежние значения (161 / 1288 / 107) были перепутаны: 55 плоских граней исчезли при
   переходе v4 → v5, когда правило края карты убрало грани против пустоты за пределами карты.
   Это внешние данные — в декомпиляции они не проверялись; учитывать как вход от сессии стен.
