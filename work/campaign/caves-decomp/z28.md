## З28.1. Резолвер режима

### ФАКТ (Diggles.exe)

1. **`FUN_004860c0(param_1, param_2, param_3)` — резолвер «режима» в технику рендера.**
   Сигнатура по регистрам: `in_ECX` = индекс группы, `in_EDX` = указатель на поле «режим».

   Evidence: `FUN_004860c0_004860c0.c:11-41`.
2. **Значит: поле «режим» — это НЕ «режим отрисовки», а индекс 0…15 в 16-элементной таблице
   внутри записи группы.** Таблица хранит **id техник рендера** (из реестра З27), и по этому
   индексу выбирается одна техника для конкретного link-объекта.
   Evidence: `FUN_004860c0_004860c0.c:13-27` + структура записи техники 0x6C байт (З27.5).
3. **Структура записи группы:** шаг `0x48` = 72 байта = 18 `int`; первые 16 (`0x00…0x3C`) —
   таблица id техник по «режиму», последние 8 (`0x40…0x5C`) — прочие поля группы.
   Evidence: `FUN_004860c0_004860c0.c:20-23`, `FUN_00483d80_00483d80.c:257-262`.
4. **Менеджер шейдеров/техник — глобал `DAT_0076a2ec` (и `FUN_0045a470()`), раскладка:**
   `+0x850` — база массива техник, `+0x854` — конец массива (число техник),
   `+0x1058` — база массива таблиц групп, `+0x105C` — число групп.
   Evidence: `FUN_004860c0_004860c0.c:12, 20, 28-31`; `FUN_00483d80_00483d80.c:253-257`.
5. **Поля записи техники, которые реально читает резолвер:**
   `+0x30` — признак «есть дополнительная пара» (0 ⇒ `param_1 = -1`);
   `+0x34`, `+0x38` — два значения, возвращаемые вызывающему;
   `+0x3C` — булево (равно 1 ⇒ `param_3 = true`).
   Evidence: `FUN_004860c0_004860c0.c:32-37`.

### Что это меняет для порта

* **Пункт З24.8 закрыт по механизму:** «11 режимов» не существует; поле `link[1]` — это
  **индекс в 16-элементной таблице техник**, где таблица задаётся для группы link-записей.
  Иными словами, одна и та же техника рендера может быть назначена разным link-записям
  через разные «режимы».
* **Для Godot-порта поле надо хранить как есть** (0…15) и маппить на свои материалы/шейдеры;
  если порт не поддерживает все 16 слотов, поведение link-записей разойдётся с оригиналом.
* **Подстановки 7→6, 18→19, 33→7 — это «техника недоступна в этом контексте ⇒ запасная».**
  Значит, в оригинале есть техники, применимые не ко всем типам объектов.

### Что осталось неизвестным

* **Точное соответствие «id техники → имя техники»** (0…36): требует разбора порядка
  регистраций в `FUN_00457b90` (37 записей) — id 7, 18, 33 в подстановках указаны числом.
* **Кто и как заполняет 16-элементную таблицу групп** (и что такое «группа» с точки зрения
  содержимого `.3db`): в `FUN_00483d80` таблица только читается.
* **Смысл пары `+0x34/+0x38`** (возвращается из резолвера): по контексту — параметры техники
  (например, идентификатор шейдера и номер стадии), но не подтверждено.
