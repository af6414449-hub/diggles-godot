## З24.5 — Выбор конкретного шаблона `Hol` в LG и смысл долей 0.287 / 0.185 / 0.077 / 0.105

*(Разобран субагентом-Explore; дефолт веса закрыт дополнительной проверкой — см. §5.4.)*

### ФАКТ: доли — это **вес группы шаблонов**, а не вероятность и не доля площади

Скрипт: `data/Scripts/classes/story/story.tcl:141-146`

(комментарий в скрипте `story.tcl:147`: `//lg_set_templategroupvalue $zone.Std.Hol 0.36` — «норма» 0.36)

Обработчик `CTclGlobalMethods__LGSetTemplateGroupValue_0064e950.c`:
* `:69` `local_18 = FUN_0058a820()` — синглтон LG (`DAT_00772414`, конструктор `FUN_00581470`);

Массив записей шаблонов: база `*(LG+0x1a4)`, счётчик `LG+0x1a8`, **шаг 0x54**; вложенный менеджер шаблонов — `LG+0x19c`

### ФАКТ: где используется вес

Только в скоринге `FUN_00586710` (0x586710), `:265`:
```
score = ROUND((2*fVar13 + штраф*100 + gamecount*200 + levelcount*250 + rand01*(1-local_2c) + 0.5)
               * *(float *)(param_1 + 0x3c)      // <- вес группы
               * 100.0 * local_18)
```
`rand01 = (rand() & 0x7fff) / 32768`.

### ФАКТ: посадка шаблона

* Позиция — `FUN_005862c0_005862c0.c:72-99`: свободное место =
  (ширина карты − ширина шаблона − 4) × (высота − высота − 4); до **16** случайных попыток
  `((rand & 0x7fff) % size) & ~3) + 4` (координаты кратны 4).
* `FUN_005842c0_005842c0.c` (посадка): `:34` координаты кратны 4; `:41-49` вписывание в карту
  (`LG+0x50..0x5C`); `:52-73` **свободность по bitmap `LG+0x84`**; `:79-100` флаги `record+0x18`
  подрезают прямоугольник; `:121` `|0x80` — «мягкая» зона, `:161` `=2` — «жёсткая»;
  `:176` `LG+0xA0 += w*h`; `:200-212` запись в список уровня `LG+0x184` (шаг 0x10: индекс, x, y, флаг);
  `:213-225` **если `record+0x41` (пещера)** → в `LG+0x18C` (шаг 0xC) добавляется
  «запретный круг» (x, y, площадь), счётчик `LG+0x190`.
* «Свободен?» `FUN_0058a510` (0x58a510) — отдельная проверка по карте:
  `:34-37` границы (с запасом 8 клеток), `:38-57` обход клеток `FUN_00592f10(x,y)` →
  **`cell+0x13 & 1` = занято** ⇒ отказ; при успехе размещение пишется в `LG+0x17C` (шаг 0x10):
  `[0]`=индекс шаблона, `[4]`=x, `[8]`=y.

### ФАКТ (доп. проверка): дефолтный вес записи = 1.0

`FUN_00583080:21` вызывает `FUN_0058f7d0(1)` (резерв 1 элемента массива шаблонов).
При `param_1 == 1` → `FUN_0058f7d0_0058f7d0.c:30` `FUN_005904f0()` — инициализация одной записи:

```
FUN_005904f0_005904f0.c:35  in_ECX[2]  = 0;          // +0x08 ширина
:36                         in_ECX[3]  = 0;          // +0x0C высота
:37                         in_ECX[7]  = 0x7fffffff; // +0x1C gamecount
:38                         in_ECX[8]  = 0x7fffffff; // +0x20 levelcount
:39                         *(in_ECX+0xb) = 0;       // +0x2C
:40                         in_ECX[10] = 0x3f000000; // +0x28 = 0.5f
:41                         in_ECX[0xc] = 0;         // +0x30
:42                         in_ECX[0xf] = 0x3f800000; // +0x3C = 1.0f  <= ВЕС ПО УМОЛЧАНИЮ
:43                         in_ECX[6]  = 0;          // +0x18 флаги
:44                         *(undefined2*)(in_ECX+0x10) = 0;   // +0x40
:45-47                      in_ECX[0x11..0x13] = 0xffffffff;  // +0x44,+0x48,+0x4C

```
(идентичная инициализация продублирована для n>1 в `FUN_0058f7d0:38-78`, там же `puVar4[0xf] = 0x3f800000`)

**Следствие:** записи шаблонов, для которых группу не задавали (все `Gng` и `Gsg`), имеют вес **1.0**,
а записи группы `Std.Hol` получают 0.287 / 0.185 / 0.077 / 0.105.

Так как сортировка — **по возрастанию score**, а вес домножает score, то:
* шаблоны `Hol` имеют **меньший** score, чем `Gng`/`Gsg` (вес 1.0) ⇒ **Hol ставятся раньше**;
* внутри группы `Hol` порядок определяется базовой суммой скоринга, вес общий для всей группы;
* чем меньше доля (Kristall 0.077), тем раньше группа попадает в очередь.

Т.е. «доли» — это **множитель штрафа/стоимости**, а не вероятность и не доля площади уровня.

### Связь с зонами 0x58xxxx (премисса подтвердилась)

`FUN_0058a820` (0x58a820) — ленивый геттер синглтона LG (`DAT_00772414`), конструктор `FUN_00581470` (0x581470).
В нём:
* **`LG+0x28` / `LG+0x2C` — массив cave-скинов, шаг 0x1C** (`CTclClassDefMethods__AddCaveSkinClass_00617570.c:145-166`);
* **`LG+0x30` / `LG+0x34` — массив «зон» (прямоугольников), шаг 0x14**
  (читатели: `FUN_0058ec00`, `FUN_0058eb30`, `FUN_0058ecd0`, `FUN_0058ba00`).

Флаг «пещера» ставится **по имени файла**: `FUN_00583080_00583080.c:38-48` — если имя содержит `"_hol_"`
⇒ `record+0x41 = 1`, `record+0x48 = −2`; тип зоны `record+0x4C` по префиксу
(`urw_`→0, `swf_`→1, `kris_`→2, `lava_`→3, `:49-78`).
Пещера при посадке пишет «круг» в `LG+0x18C`, а скоринг (`FUN_00586710:61-88`) отвергает всё, что
попадает в этот круг ⇒ **Hol = крупные блокирующие объекты: их ставят первыми, остальное обтекает**.

### ЗАКРЫТИЕ открытого вопроса субагента

* «Кто читает массив cave-скинов `LG+0x28` (шаг 0x1C) — не найден» → **найден**:
  `FUN_0058e9c0_0058e9c0.c:25-52` (см. З24.2) — читает `in_ECX+0x28`/`+0x2c` с шагом 0x1c и
  сравнивает `rec[+0x0c]` (iSize) / `rec[+0x10]` (iSet) / `rec[+0x14]` (iDetail);
  вызывается из `FUN_0058ba00:228-242`, который, в свою очередь, вызывается из
  `CTclGlobalMethods__DigApply_006347a0.c:129`.
* «Дефолт `+0x3C` для Gng/Gsg неизвестен» → **закрыто**: `1.0f` (`FUN_005904f0:42`, `FUN_0058f7d0:67`).

### Что осталось неизвестным

1. Точная семантика массива ограничений `LG+0x68` (шаг 0xC) и поля `local_18` в скоринге.
2. `FUN_00587480` (0x587480, ~9 КБ) прочитан не полностью: как группа `LG+0xA4` раскладывается
   в набор шаблонов и как сопоставляется с местом.
3. Как `LG+0x194/0x198` (стартовый шаблон) связывается с `FUN_00587480` — не прослежено до конца.
4. Не проверено визуально: фактический порядок и выбор шаблонов в игре.
