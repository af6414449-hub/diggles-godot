## З36. Семантика записи техники (0x6C Б): полная карта полей и связь с портом

*(закрывает п. 1 из «Что осталось неизвестным» в З31 и частично п. 4 в З32; все имена полей взяты из самого `Diggles.exe` — из парсера и экспортёра определений техник)*

### 1. Откуда взялись имена полей

**ФАКТ (Diggles.exe):** движок умеет **читать** и **выгружать** определения техник, и в обоих случаях использует **одни и те же имена параметров**:

* чтение — `FUN_0045c970_0045c970.c` (парсер файла определений);
* выгрузка — `FUN_0045b7b0_0045b7b0.c` (экспорт техники), `FUN_0045bff0_0045bff0.c` (экспорт шейдера);
* строки имён в exe: `0x723660…` (имена для парсера) и `0x7233A8…` (форматы для экспорта).

Список имён (парсер / экспорт, в одном порядке):

```
zenable          zwriteenable     zfuncmode        alphaenable
alphatestenable  alphafuncmode    alpharefvalue    srcblendmode
destblendmode    specularenable   cullmode         lighting
glowenable       glowsize         glowcolor        envmapenable
textstage0 … textstage7          (подпараметры стадии — см. §4)
```

**ФАКТ (Diggles.exe):** экспортёр пишет поля **строго по порядку**, и этот порядок совпадает с порядком полей в записи:
`FUN_0045b7b0.c:91` (`zenable`, `param_2[0]`) → `:105` (`zwriteenable`, `param_2[1]`) → `:116` (`zfuncmode`, `param_2[2]`) → `:130` (`alphaenable`, `param_2[3]`) → `:144` (`alphatestenable`, `param_2[4]`) → `:155` (`alphafuncmode`, `param_2[5]`) → далее `alpharefvalue` … `envmapenable` (`param_2[6] … param_2[15]`).

**ФАКТ (Diggles.exe):** парсер пишет в **те же** смещения:
`FUN_0045c970.c:288` (`zenable` → `param_3[0]` = +0x00), `:304` (`zwriteenable` → `param_3[1]` = +0x04), `:319` (`zfuncmode` → `param_3 + 2` = +0x08), `:325` (`alphaenable` → `param_3[3]` = +0x0C), `:521` (`alphatestenable` → `param_3[4]` = +0x10), `:342` (`alphafuncmode` → `param_3 + 5` = +0x14), `:348` (`alpharefvalue` → `param_3[6]` = +0x18), `:358` (`srcblendmode` → `param_3 + 7` = +0x1C), `:371` (`destblendmode` → `param_3 + 8` = +0x20), `:377` (`specularenable` → `param_3[9]` = +0x24), `:392` (`cullmode` → `param_3 + 10` = +0x28), `:398` (`lighting` → `param_3[0xb]` = +0x2C), `:414` (`glowenable` → `param_3[0xc]` = +0x30), `:441` (`glowsize` → `param_3[0xd]` = +0x34), `:435` (`glowcolor` → `param_3 + 0xe` = +0x38), `:453` (`envmapenable` → `param_3[0xf]` = +0x3C), `:491` (`textstageN` → `param_3[N − 0x1F]`, N = `'0'`…`'7'` ⇒ **+0x44 … +0x60**).

### 2. Полная карта записи техники (0x6C Б)

| смещение | имя | тип | значения в 37 поставляемых техниках |
|---|---|---|---|
| +0x00 | **ZEnable** | флаг | 1 / 0 (0 у `interface_*` — GUI без z-теста) |
| +0x04 | **ZWriteEnable** | флаг | 1 / 0 (0 у `model_solid_nozwrite`, `model_blend_nozwrite`, `model_additive`, `model_additive_envmap`? — см. `z31_shaders.tsv`) |
| +0x08 | **ZFuncMode** | D3DCMP | 8 = NEVER (GUI), 4 = LESSEQUAL (обычный), 2 = LESS (`scape_fow`, `scape_solid`, `shadow_blend`, `obj_glow`) |
| +0x0C | **AlphaEnable** | флаг | 1 у blend/additive, 0 у solid |
| +0x10 | **AlphaTestEnable** | флаг | 1 у `model_blend`, `scape_solid`, `scape_blend`, `shadow_blend`, `water_blend`, `sulfur_blend`, `lava_blend`, `interface_glow`, `scape_multi_lav_fow` |
| +0x14 | **AlphaFuncMode** | D3DCMP | 8 = NEVER (тест выключен), 5 = GREATER (тест включён), 4 = LESSEQUAL (`model_solid_invalpha`) |
| +0x18 | **AlphaRefValue** | 0…255 | 127 (`model_solid`, `model_solid_nozwrite`), 126 (`scape_solid`), иначе 0 |
| +0x1C | **SrcBlendMode** | D3DBLEND | 2 = ONE (solid), 5 = SRCALPHA (blend/additive) |
| +0x20 | **DestBlendMode** | D3DBLEND | 1 = ZERO (solid), 2 = ONE (additive), 6 = INVSRCALPHA (blend) |
| +0x24 | **SpecularEnable** | флаг | 1 у `model_blend_envmap`, `model_additive_envmap` |
| +0x28 | **CullMode** | D3DCULL | 1 = NONE (двусторонний: `interface_*`, `scape_fow`, `scape_solid`), 2 = CCW, 3 = CW (по умолчанию) |
| +0x2C | **Lighting** | флаг | 1 по умолчанию, 0 у `nolight_noalpha` |
| +0x30 | **GlowEnable** | флаг | 1 у `model_additive_glow`, `model_blend_glow`, `particle_*`, `alpha_light`, `sky_blend` |
| +0x34 | **GlowSize** | целое | 50 у glow-техник, иначе 0 |
| +0x38 | **GlowColor** | 0xAARRGGBB | `0xFFFFFF` у glow-техник, иначе 0 |
| +0x3C | **EnvMapEnable** | флаг | 1 у `model_blend_envmap`, `model_additive_envmap` |
| +0x40 | *(внутреннее, не экспортируется и не задаётся из Tcl)* | — | всегда 0 в поставляемых техниках |
| +0x44…+0x60 | **TextStage0 … TextStage7** | id материала | заполнены только стадии 0 и 1 (см. §5) |
| +0x64 | имя техники | строка | |
| +0x68 | имя родителя | строка | (`"disable"` у корня) |

**ФАКТ (Diggles.exe):** значения `ZFuncMode`/`AlphaFuncMode` — это константы **Direct3D 7** (`D3DCMP_NEVER=1, LESS=2, EQUAL=3, LESSEQUAL=4, GREATER=5, NOTEQUAL=6, GREATEREQUAL=7, ALWAYS=8`); имена сравнений лежат в exe строкой: `0x722CCC` `never`, `0x722CDC` `equal`, `0x722CE4` `lessequal`, `0x722CF0` `greater`, `0x722CF8` `notequal`, `0x722D04` `greaterequal`.
**ФАКТ (Diggles.exe):** значения `SrcBlendMode`/`DestBlendMode` — константы **D3DBLEND**: `0x722D28` `srccolor`, `0x722D34` `invsrccolor`, `0x722D40` `srcalpha`, `0x722D4C` `invsrcalpha`, `0x722D58` `destalpha`, `0x722D64` `invdestalpha`, `0x722D74` `destcolor`, `0x722D80` `invdestcolor`, `0x722D90` `srcalphasat`, `0x722D9C` `bothsrcalpha`, `0x722DAC` `bothinvsrcalpha` ⇒ `1 = ZERO`, `2 = ONE`, `5 = SRCALPHA`, `6 = INVSRCALPHA`.
**ФАКТ (Diggles.exe):** `CullMode` — `1 = NONE`, `2 = CCW`, `3 = CW` (значения из `z31_shaders.tsv`: 1 у двусторонних, 3 по умолчанию).

**⇒ ОПРОВЕРЖЕНИЕ гипотезы З31 (важно).** В З31 было предположено: «+0x20 = режим смешивания (1 = без смешивания, 2 = additive, 6 = alpha)». **Это неверно по смыслу**: `+0x20` — это **DestBlendMode**, а `+0x1C` — **SrcBlendMode**. Пара (Src, Dest) всегда осмысленная:
`(2, 1)` = ONE/ZERO = **непрозрачно**; `(5, 6)` = SRCALPHA/INVSRCALPHA = **alpha-blend**; `(5, 2)` = SRCALPHA/ONE = **additive**. Тот же вывод даёт §5 (порт эмулирует `WRAPPED_D3DTSS_*`, а смешивание — отдельное состояние).

### 3. Кто читает поля записи

**ФАКТ (Diggles.exe):** `FUN_004860c0_004860c0.c` — «режим → техника» (резолвер):
- `:11` — менеджер рендера; `:20` — **таблица групп материалов** (`manager + 0x1058`, шаг **0x48** на группу, внутри 16 dword = слоты режимов 0…15);
- `:27-31` — id техники из слота ⇒ **запись техники** = `manager + 0x850` + `id * 0x6C`;
- `:33-36` — если `GlowEnable (+0x30) != 0` → наружу отдаются `GlowSize (+0x34)` и `GlowColor (+0x38)`;
- `:37` — `EnvMapEnable (+0x3C) == 1` → наружу отдаётся булев флаг.

**ФАКТ (Diggles.exe):** `FUN_00450850_00450850.c:65` — читает `+0x0C` (**AlphaEnable**): если 0 ⇒ «настоящего шейдера нет»; `:76` — читает `+0x20` (**DestBlendMode**): `!= 1` (≠ ZERO) ⇒ непрозрачный ⇒ «настоящий шейдер» есть. Это и есть те самые два признака из З34 (бит 17 ключа сортировки).

**ФАКТ (Diggles.exe):** все восемь функций применения техники (`FUN_004899b0`, `FUN_0048a240`, `FUN_0048aa60`, `FUN_0048b290`, `FUN_0048ba80`, `FUN_0048c3f0`, `FUN_0048d490`, `FUN_0048dce0`) проверяют `+0x04` (**ZWriteEnable**):
`FUN_004899b0.c:290`, `FUN_0048a240.c:256`, `FUN_0048aa60.c:276`, `FUN_0048b290.c:256`, `FUN_0048ba80.c:281`, `FUN_0048c3f0.c:291` — «если ZWrite выключен — другая ветка вывода». Это согласуется с именами `model_solid_nozwrite` / `model_blend_nozwrite`, у которых `+0x04 = 0`.

**ФАКТ (Diggles.exe):** `FUN_00451600_00451600.c:312` — читает `+0x28` (**CullMode**).

**ФАКТ (Diggles.exe):** `FUN_00457b90_00457b90.c` (регистрация 37 техник) проставляет **только отличающиеся от `default` поля** — например для `interface_blend`: `local_24[0]=0, [1]=0, [2]=8, [3]=1, [7]=5, [8]=6, [10]=1, [0xb]=0, [0x11]=0xb` (`:70-78`) ⇒ +0x00=0, +0x04=0, +0x08=8, +0x0C=1, +0x1C=5, +0x20=6, +0x28=1, +0x2C=0, **+0x44=11**.

### 5. Контракт с портом: `data/Shaders/Common.fxh`

**ФАКТ (игра, порт):** порт **эмулирует fixed-function стадии DD7 в HLSL**:
- `data/Shaders/Common.fxh:50-76` — структура `TextureStageOptions` с полями `WRAPPED_D3DTSS_COLOROP, COLORARG1, COLORARG2, ALPHAOP, ALPHAARG1, ALPHAARG2, BUMPENVMAT00..11,_TEXCOORDINDEX, ADDRESS, ADDRESSU, ADDRESSV, BORDERCOLOR, MAGFILTER, MINFILTER, MIPFILTER, MIPMAPLODBIAS, MAXMIPLEVEL, MAXANISOTROPY, BUMPENVLSCALE, BUMPENVLOFFSET, TEXTURETRANSFORMFLAGS` (24 dword = 96 Б на стадию);
- `:42-43` — **`USED_STAGES_COUNT 2`**, `MAX_STAGES_COUNT 8` ⇒ в игре реально используются **две** текстурные стадии, и в записи техники заполнены только `+0x44` (стадия 0) и `+0x48` (стадия 1) — это совпадает с `z31_shaders.tsv`, где `+0x4C…+0x60` всегда 0;
- `:78-90` — `cbuffer b0 = { WVP, wndrect, rendopt, rendopt2, rendopt3 }`, `cbuffer b1 = { texStageOptions[8] }`;

- `:118-124` — `rendopt[2]` = **SpecularEnable**;
- `:108-116` — `rendopt.w` = «выбранный цвет» (override);

### 6. Что это меняет для порта

1. **Запись техники — это fixed-function состояние, а не «шейдер».** Порт должен хранить те же 16 флагов/режимов + состояние 2 стадий. Готовый HLSL-эмулятор в `Common.fxh` уже есть — ему нужен только правильный заполненный буфер.
2. **Смешивание задаётся парой (Src, Dest), а не одним флагом.** `(2,1)` = opaque, `(5,6)` = alpha-blend, `(5,2)` = additive. Если в порте стоит «один bool на прозрачность» — будут расхождения в порядке и в альфе.
3. **Z-функция различает NEVER / LESSEQUAL / LESS** — GUI (NEVER), обычная земля (LESSEQUAL), туман войны и тени (LESS). В D3D11 это `DepthStencilState` c тремя разными ComparisonFunc.
4. **Альфа-тест включается отдельным флагом** (`+0x10`), функция сравнения — отдельным полем (`+0x14`), порог — третьим (`+0x18`, 127/126). Порог **127** у `model_solid` — это «пиксель непрозрачен на 50 %».
5. **`CullMode` = NONE (1) у двусторонних техник** (земля, GUI) — в D3D11 это `CullMode.None`; по умолчанию CW (3) — обратная сторона отсекается.
6. **ZWriteEnable — отдельный флаг**, а не следствие прозрачности: `model_solid_nozwrite` и `model_blend_nozwrite` — это техники с `+0x04 = 0`.
7. **Glow — это (размер, цвет) в технике**, а не отдельный шейдер: `GlowEnable`, `GlowSize = 50`, `GlowColor = 0xFFFFFF`.
8. **Порядок отрисовки (З34) зависит ровно от двух полей**: `+0x0C` (AlphaEnable) и `+0x20` (DestBlendMode ≠ ZERO). Это надо воспроизвести буквально, иначе прозрачные объекты лягут не в том порядке.

### 7. Что осталось неизвестным (и как проверить)

1. **Смысл поля `+0x40`** — не экспортируется, не задаётся из Tcl, во всех 37 техниках равно 0. **Проверка:** найти читателя `+0x40` записи техники (искать `+ 0x40` рядом с `* 0x6c`).
2. **Пространство имён `TextStage0..7`**: значения — id в общем хеш-реестре имён (`FUN_00444990`, 256 корзин, поиск по хешу `hash*9` и бинарным поиском внутри корзины; `FUN_0045aa00` использует тот же реестр для имён техник). Пул имён (exe, `0x722DC4…`): `model, scape_st, scape_urw_mt0, scape_urw_mt1, scape_lav_mt0, scape_lav_mt1, fogofwar, interface0, interface1, interface2, interface1filter, alpha_light0, alpha_light1, water_mt0, water_mt1, sulfur_m, sulfur_mt1, lava_mt0, lava_mt1, nolight_noalpha` + имена 37 техник. **Точный порядок регистрации (id → имя) не восстановлен** — известно лишь, что значения идут **парами (X, X+1)** (два слоя текстуры): `scape_multi_urw` → (4,5), `scape_multi_lav` → (6,7), `sky_blend_multi` → (9,10), `alpha_light` → (15,16), `water_blend` → (17,18), `sulfur_blend` → (19,20), `lava_blend` → (21,22). **Проверка:** снять дамп реестра в рантайме (обойти 256 корзин) и сопоставить.
3. **Кто именно ставит `+0x10` = 1** (AlphaTestEnable) — из кода видно только, что техники с альфа-тестом имеют `+0x14 = 5` (GREATER) и ненулевой `+0x18`.
4. **Читатели `+0x08`, `+0x28`, `+0x30`, `+0x38` в самом движке** — часть полей, судя по всему, потребляется только портом (D3D11) через `DigglesPort.dll`; в exe найдены потребители не всех полей.
5. **Ни одно утверждение не сверено с живой игрой** — всё статическое.
