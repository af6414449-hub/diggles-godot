### 1. Сетка 8×8 внутри блока: индекс = (y&7)<<3 | (x&7)

То есть **строка = Y, столбец = X**.

* `FUN_00407e70_00407e70.c:8` — `((param_2 & 7) << 3 | param_1 & 7) + 0x3c + iVar1` (карта состояния клетки `cell+0x3c`).
* `FUN_004093f0_004093f0.c:20-21` — высота из блока: `((param_2 & 7) << 3 | param_1 & 7) + iVar3`.
* `FUN_00595e40_00595e40.c:113-129` — построчное копирование 8×8 блока в сетку: внешний цикл = строка клетки (Y), внутренний = столбец (X).
* `FUN_00596550_00596550.c:108-124` — запись `cell+0x3c`, индекс `строка*8 + столбец`.

### 2. Оси: X — восток (вправо), Y — низкий Y = север (верх карты)

* `FUN_005fc9d0_005fc9d0.c:86-104`: бит 4 гасит **левую** половину по X, бит 8 — правую, бит 1 — **нижнюю по Y** (`iVar9 < iVar10`), бит 2 — верхнюю.
* `CTclGlobalMethods__SMDrawStone_0065e090.c:927` — полоса «север» (`flag=1`) рисуется по `y ∈ [0, 0x20]` (низкий Y); `:932` — «запад» (`flag=4`) по `x ∈ [0, 0x20]`; `:938` — «восток» (`flag=8`) по правому краю.

### 4. Доказательство А — код: `FUN_005968b0` (прочность породы вокруг точки выемки)

Функция берёт **четыре клетки вокруг вершины (x,y)** и для каждой — дочерний блок и материал квадранта:

| клетка | слот дочернего блока | байт материала | строки кода |
|---|---|---|---|
| (x−1, y−1) | `+0x4c` | `+0x53` | `FUN_005968b0_005968b0.c:19-49` |
| (x, y−1) | `+0x48` | `+0x52` | `:50-80` |
| (x−1, y) | `+0x44` | `+0x51` | `:81-111` |
| (x, y) | `+0x40` | `+0x50` | `:112-147` |

Возвращается **максимум из четырёх материалов** (`:148-160`); если хотя бы у одного угла нет дочернего блока — `0xffffffff` (`:133-135`).

### 5. Доказательство Б — код: выбор дочернего блока при выемке (`FUN_00596b80`)

Четыре независимых блока кода, по одному на каждую из четырёх клеток вокруг вершины; порядок обхода — SE → SW → NE → NW:

| # | клетка | слот | материал | координаты (дизасм) |
|---|---|---|---|---|
| A | (x−1, y−1) | `+0x4c` | `+0x53` | `0x596CB7` / чтение слота `0x596CF2` |
| B | (x, y−1) | `+0x48` | `+0x52` | `0x596D20` / `0x596D5B` |
| C | (x−1, y) | `+0x44` | `+0x51` | `0x596D89` / `0x596DC4` |
| D | (x, y) | `+0x40` | `+0x50` | `0x596DF0` / `0x596E29` |

Условие приёмки дочернего блока **двойное**:

1. *геометрическое* — какой слот вообще рассматривается, задаётся структурой кода (номер квадранта клетки относительно вершины), не рантайм-веткой;
2. *материальное* — `child_id != -1 && child->material_byte == FUN_005968b0()`; иначе в клетке остаётся родительский блок.

Evidence: `FUN_00596b80_00596b80.c:68-69` (`+0x4c`/`+0x53`), `:82-83` (`+0x48`/`+0x52`), `:96-97` (`+0x44`/`+0x51`), `:110-111` (`+0x40`/`+0x50`).
Запись результата: `cell[0x00] = выбранный блок`, `cell[0x13] |= 1` (`0x596E64`, `0x596EB0`, `0x596ED3`).

## Что это меняет для порта

* **Квадранты блока читаются так:** `+0x40`/NW (левый-верхний), `+0x44`/NE (правый-верхний), `+0x48`/SW (левый-нижний), `+0x4c`/SE (правый-нижний); материалы квадрантов — `+0x50…+0x53` в том же порядке.
* **«Твёрдость породы» в точке выемки = максимум материалов четырёх квадрантов вокруг вершины**, а материал берётся из дочернего блока (если он есть), иначе из родительского; если дочернего блока нет ни у одного из четырёх углов — «непреодолимо» (`0xffffffff`).
  ⇒ Это значение **вычислимо из BDB** (ID дочерних блоков + материалы квадрантов), но **не** из одной карты высот 8×8.
* Место в порту: правила копания/проходимости, если порт их когда-нибудь реализует; сейчас порт копание не моделирует.

## Что осталось неизвестным

* Почему ребёнок хранится в BlockDB как отдельный **полный** 8×8-блок, а не как патч 4×4; есть ли в записи блока 0x59 байт для «структуры квадранта» — не найдено.
* Семантика байтов `block+0x54…+0x58` (остаток записи блока).
* Не проверено, в какой игровой момент выбирается, какая именно вершина выемки (`CTclGlobalMethods__DigApply_006347a0.c:92-116` берёт координаты из позиции объекта) — подтверждено лишь, что выемка привязана к вершине сетки клеток.
* Эмпирика п. 6 выполнена только по `BlockDB0.BDB` (на BDB1/BDB2 не перепроверялось; содержимое всех трёх статистически идентично).
