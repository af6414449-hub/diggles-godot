## З27.2. Формат вершины: свет запечён в цвете вершины

### ФАКТ (`Common.fxh`, `UL1CS.fx`)

1. **Вершинный формат:**
   ```
   float3 crd : POSITION;   dword diffuse : COLOR0;   dword specular : COLOR1;
   float2 uv  : TEXCOORD0;  (float2 uv[2] — в 2CS-вариантах)
   ```
2. **`UnpackColor(dword)` — упакованный ARGB:**
   `A = (v & 0xFF000000) >> 24`, `R = (v & 0x00FF0000) >> 16`, `G = (v & 0x0000FF00) >> 8`,
   `B = v & 0xFF`; результат делится на 255.
3. **Шейдер НЕ делает освещения.** Он берёт `diffuse` и `specular` из вершины, применяет
   эмуляцию текстурных стадий, добавляет `spec` и гамму:
   ```
   float4 spec  = CheckSpecularEnabled(input.specular);
   float4 color = TextureStaging(uv, input.diffuse, spec);
   color.rgb += spec.rgb;
   return ApplyGamma(AlphaTest(color));
   ```
   ⇒ **весь свет (диффузный и зеркальный) считает движок на CPU** и кладёт в цвет вершины.
   Evidence: `Common.fxh:92-100`; `UL1CS.fx` (блок `PS`); сравнимо с `FUN_00485370`
   («свет/дымка в вершинах», З24.10).
4. **Спекуляр гасится флагом:** `CheckSpecularEnabled` возвращает `spec` только если
   `rendopt[2] != 0`, иначе ноль ⇒ спекуляр включается/выключается материалом.

### Что это меняет для порта

* **Godot-порт обязан считать свет так же — в цвете вершины**, иначе картинка не совпадёт:
  никакого realtime-света Godot, никакого Environment-освещения. В оригинале цвет вершины =
  «материал × свет × дымка/туман войны» (см. `FUN_00485370`).
* **Формат вершины оригинала известен точно** (POSITION + COLOR0(diffuse) + COLOR1(specular) +
  TEXCOORD0, 1 или 2 набора UV) — это прямо задаёт формат мешей при переносе.

## З27.3. Эмуляция фиксированного конвейера (D3DTSS)

### ФАКТ (`Common.fxh`)

1. **Состояния стадий приходят в constant buffer `b1`:** `TextureStageOptions texStageOptions[8]`,
   где структура повторяет D3DTSS-константы: `COLOROP, COLORARG1, COLORARG2, ALPHAOP,
   ALPHAARG1, ALPHAARG2, TEXCOORDINDEX, ADDRESS, MAGFILTER, MINFILTER, MIPFILTER,
   MAXANISOTROPY, TEXTURETRANSFORMFLAGS` и др.
   ⇒ **движок передаёт в шейдер свои D3D render-state**, а шейдер их исполняет.
2. **Реализованы операции:** `DISABLE, SELECTARG1, SELECTARG2, MODULATE, MODULATE2X, MODULATE4X,
   ADD, ADDSIGNED, ADDSIGNED2X, SUBTRACT, ADDSMOOTH, BLENDTEXTUREALPHA`.
   **Не реализованная операция возвращает мадженту `(1.0, 0.2, 0.5, 1.0)`** — в коде комментарий
   «implement other operations if you see this color». Это встроенный диагностический признак.
3. **Аргументы стадии:** `DIFFUSE / CURRENT / TEXTURE / TFACTOR / SPECULAR`; `TFACTOR`
   берётся из `rendopt2[0]`.
4. **Реализованы только 2 стадии из 8** (`USED_STAGES_COUNT = 2`) — остальные слоты массива
   существуют, но не используются.
5. **Alpha test:** `rendopt2[1]` — вкл/выкл, `rendopt2[2]/255` — порог, `rendopt2[3]` — функция
   сравнения (NEVER/LESS/LESSEQUAL/GREATER/GREATEREQUAL/EQUAL/NOTEQUAL/ALWAYS);
   `ALWAYS` → `discard`, остальные → `clip`.
6. **Отдельный «выбор цвета»:** `ChangeIfSelected` — если `rendopt.w` содержит цвет с `alpha > 0`,
   он заменяет цвет пикселя (подсветка выбранного объекта).

### Что это меняет для порта

* **Порядок операций строго задан:** текстура/диффуз → стадии → спекуляр → **alpha test** →
  **гамма**. Если в Godot-порте гамма применяется до alpha test или после blend — картинка
  разойдётся.
* **«Текстурные стадии» в оригинале — это 2 слоя текстуры, смешиваемых по D3DTSS-правилам.**
  Godot-порту достаточно двух TextureStage-подобных умножений/сложений; полный набор D3DTOP
  не требуется.

## З27.4. Гамма и пост-обработка

### ФАКТ (`Gamma.fxh`, `BloomBrightness.fx`, `Blur*.fx`, `Composition.fx`)

1. **Гамма (`Gamma.fxh`):** `color.rgb = pow(color.rgb, 1/gamma)`, затем
   `color.rgb = saturate(color.rgb + brightness)`. Диапазоны: `gamma` 0.3…2.3,
   `brightness` −0.5…0.5. `ApplyGamma` = `lerp(color, GetGamma(color), apply)` — «apply» из
   `cbuffer b2` ⇒ гамма может быть выключена для части материала.
2. **Яркость сцены:** `luminosity = dot(float3(0.2126, 0.7152, 0.0722), color.rgb)` (Rec.709).
3. **Порог блума:** `scene_luminosity = (clamp(scene_brightness, 0.1, 0.2) - 0.1) * 10`
   (то есть 0…1), `scene_threshold = lerp(0.70, 1.0, scene_luminosity)`,
   `luminance = clamp(brightness - threshold, 0, 1) / 0.3`, вклад `× 1.5`.
4. **Размытие:** 5-тапное гауссово, веса `0.227027, 0.1945946, 0.1216216, 0.054054, 0.016216`
   (сумма 1.0), отдельно по X и по Y, шаг — `tixel_width/height`.
5. **Композиция:** `color = offscreen + bloom * bloom_intensity`; затем
   `color.b *= lerp(0.8, 1.0, scene_luminosity)`, `color.g *= lerp(0.97, 1.0, scene_luminosity)`
   (синий и зелёный гасятся при тёмной сцене — «цветовая коррекция»); в конце — `GetGamma`.
6. **Вертикальный флип:** `WindowToScreenCoord` даёт `y = 1 - h/(wndrect.y/2)`
   ⇒ переход из D3D (y вниз) в D3D11 NDC (y вверх).

### Что это меняет для порта

* **Гамма — часть материала, а не пост-обработка сцены:** в оригинале `ApplyGamma` вызывается
  в каждом материале (`Straight`, `UL*`, `TL*`), а в `Composition` — ещё раз (`GetGamma`).
  Godot-порт обязан учитывать это двойное применение, иначе тени и полутона «поплывут».
* **Bloom включается опционально и зависит от `scene_brightness`**; его порог и веса известны
  точно ⇒ можно воспроизвести 1:1.
* **Цветовая коррекция в финальной композиции (B×0.8…1.0, G×0.97…1.0)** — часть оригинальной
  картинки; без неё сцены будут «холоднее».

## З27.6. Что осталось неизвестным

* **Семантика полей записи техники** (0x6C байт): что означают `state[2]` (=8 у большинства),
  `state[7]`, `state[8]` (2/6/1 — варьируется), `state[10]`, `state[11]`, `state[17]` (=11 у части).
  Нужен разбор потребителя (какой код читает эти поля и как ставит D3D-состояния).
* **Когда выбирается `UL*`, а когда `TL*`:** по типу прохода (3D-мир vs экранные координаты)
  не установлено; `TL` использует оконные координаты ⇒ вероятно 2D-слой/интерфейс/декали.
* **Как выбирается `1CS` против `2CS`** (одна или две текстурные стадии): предположительно —
  по материалу (есть вторая текстура — карта чего-то), но не доказано.
* **Неизвестно, как `scape_fow` реализует туман войны**: через цвет вершины (вероятно,
  cf. `FUN_00485370`) или через отдельную текстуру.
* **Список `.fx` может различаться в сборке GOG** (там заявлен D3D11) — не проверялось.
* **Ни один параметр из этих шейдеров не сверен с живой игрой** — статический разбор.
