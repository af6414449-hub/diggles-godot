# Diggles: The Myth of Fenris — реимплементация на Godot 4.7.2

Source-first реверс-инжиниринг и порт экономико-стратегической игры-«гномокопатель»
**Diggles: The Myth of Fenris** (в Европе — «Wiggles», SEK GmbX / Innonics, 2001–2002)
на **Godot 4.7.2** — с оригинальной механикой, а не с придуманной.

> **Статус:** приватный репозиторий, активная разработка. Проект никогда не был под
> системой контроля версий до этого коммита — вся история велась по копиям деревьев
> и датам. Текущее состояние проекта описано в `PROJECT-MAP-2026-11-21.md`.

---

## Что это

Diggles — RTS/экономика про гномов, которые копают руды, строят фермы, воюют с
созданиями и живут по расписанию. Оригинал 2001 года: движок на **C++ с собственным
D3D-рендерером** и скриптовый слой на **Tcl**. Данные игры лежат в бинарных форматах
(PMP-карты, 3DB-модели, BlockDB-высоты), правила частично живут в `.tcl`-скриптах.

Проект читает оригинальные данные **только на чтение** и воспроизводит их поведение
в GDScript. Не «игра inspired by Diggles», а попытка сделать так, чтобы глава
проходилась так же, как в оригинале.

## Зачем

**Цель:** самостоятельная Android-реализация — игрок проходит главу целиком,
и глава собрана так же, как в оригинале.

**Критерий готовности:** APK с первой главой, 30 FPS на Vivo.

| Шаг | Что значит «готово» | Состояние |
|---|---|---|
| **A. Генератор уровня кампании** | глава собирается из оригинальных шаблонов детерминированно по seed | закрыт, требуется свести две реализации в одну |
| **B. Гном как самостоятельный агент** | гном без приказов сам занимается делом, спит, ест, ходит на работу | не начат (блок M7) |
| **C. Экономика и фермы** | ферма производит, гномы едят и носят | частично |
| **D. Бой и враги** | бой идёт по исходной боевой таблице | не начат (блок M6) |
| **E. Сюжет и постановка** | сюжетная сцена играется, босс появляется в сцене | движок есть, не хватает диалогов и квестов |
| **F. Android-релиз** | APK с первой главой, 30 FPS на Vivo | не начат |

**Порядок работ:** B → C → E → D → F.

## Главное правило проекта: ФАКТ / АДАПТЕР / НЕИЗВЕСТНО

Каждое утверждение маркируется, и маркировка не смешивается:

- **ФАКТ** — подтверждено оригиналом: адрес в EXE, строка Tcl, байты в 3DB/PMP.
- **АДАПТЕР** — инженерное решение там, где оригинал неизвестен или неизлечим.
- **НЕИЗВЕСТНО** — так и пишем, ничего не выдумываем.

В коде это оформляется комментариями `## SOURCE:` (факт) и `## ADAPTER:` (решение
порта). Числа из исследовательских документов нельзя тащить в код как константы —
это гипотезы, пока не сверено с оригиналом.

## Быстрый старт

**Требования:** Godot **4.7.2** (режим рендера — GL Compatibility) и Python **3.11**
для инструментов. Оригинальная игра нужна только как источник фактов; читать её
данные в рантайме проект не требует.

1. Открой `godot/project.godot` в Godot 4.7.2 → импорт → **F5** (главная сцена —
   `res://scenes/campaign_first_level.tscn`).
2. Управление в главной сцене кампании: **ЛКМ** — орбита/поворот, **ПКМ** — панорама,
   **колесо** — зум, **Q**/**E** — поворот камеры, **+**/**−** — зум. Тач: один палец —
   поворот, два пальца — панорама или зум (режим фиксируется после первого движения
   и не смешивается до отпускания пальцев).
3. Отдельная сцена-референс `godot/scenes/terrain_reference.tscn` — эталонная
   сцена оригинала (`demo_start/hol_024`): **R** — сброс, **O** — смена проекции,
   **C**/**T** — служебные переключения.

Вся документация по проекту — на русском, в `docs/`.

## Тесты

Каждый блок работы проверяется self-тестом с golden-значениями: тесты лежат в
`godot/tools/*_self_test.gd`, запускаются headless через Godot.

```powershell
# все сюиты сразу; путь к Godot зашит в scripts/run_all_suites.py (GODOT = ...)
python scripts/run_all_suites.py --project godot --out out/testlogs

# отдельные сюиты
python scripts/run_all_suites.py --project godot --out out/testlogs --only native_walk_flags_self_test,native_campaign_camera_self_test
```

Прогон печатает `OK <suite> <N> assertions` и завершается строкой `ALL SUITES GREEN`.
Скрипт сам убивает зависшие процессы Godot по командной строке, чтобы не задеть
чужие сессии. Скрипт выхода `1`, если хотя бы одна сюита упала.

Точечные инструменты: `scripts/run_hamster_suites.py`, `scripts/judge_suites.py`,
`scripts/run_scene_headless.py`, `scripts/verify_patch_roundtrip.py` — у каждого
свой `--help`.

## Как устроен реверс

Источник фактов — оригинальные данные игры (Tcl-скрипты, PMP-карты, 3DB-модели,
BlockDB) и дизассемблирование EXE. Отсюда взяты конкретные числа, которые обычным
«похожим» движкам не вывести:

- **Генерация главы:** `first_level` + собственный RNG оригинала `irandom`
  + `sm_mark_temparea` + `MapTemplateSet`. Уровень — функция от seed, а не ручная
  карта; миры оригинала: Urwald → Schwefel → Metall → Lava → Kristall → 6000.
- **Шаблоны:** `urw_unq_start` (старт), `urw_hol_*` (пещеры), `urw_gng_*`
  (переходы, `urw_gng_001…045_` — вудо-шаблоны); точки соединения — `data/Templates/*.ent`.
- **Темп анимации:** контроллер оригинала отдаёт **10 кадров на игровую секунду**
  (`controller_frames_per_game_second` = 10.0, `0x007373F0`). Значение 12 fps —
  адаптер порта.
- **Сетка высот:** 8 единиц на клетку (8×8 сэмплов на клетку), `GetHMap` → `ROUND(x*8.0)`.
- **Координаты:** PMP — столбцы/строки вниз; Tcl — `(x, y, logical_z)`;
  3DB — `(local_x, local_y, render_z)`, где `render_z = 7 + logical_z/2`.
- **Карта главы:** 512×640 клеток, собрана в `godot/models/native_campaign_chapter.json`.

Подробности — в `docs/reverse-engineering/` (по адресам EXE) и `docs/research/`
(по публичным источникам).

### Навигация по карте: четыре разные сетки

Самый частый источник неверных правок — смешивание сеток. Кратко:

| Сетка | Шаг | Где подтверждено |
|---|---|---|
| Клетка карты | 1:1 с Tcl | `FUN_00592f10`, границы `map->0x84..0x90` |
| Высота / сэмпл | 8 единиц на клетку (8×8 на клетку) | `GetHMap`, `FUN_004093f0` |
| Рёбра / кромка | 4 единицы на клетку | `FUN_005fa510`, `FUN_005fd060` |
| Объект карты | вдвое больше игрового поля | `map->0x74/0x78`, `0x7c/0x80` |

Высота (`level`, байт 0…15) и world-Z связаны как `world-Z = 7.0 + 0.5 × level`.
Проходимость лежит в отдельном параллельном массиве флагов (`cell+0x3C`, 64 байта
на клетку), а не в копии высот: бит `0x01` — проходимо, `0x02` — ступень/пол,
`0x04` — объект или лестница.

**Правило:** «the original cached flags must never silently survive excavation» —
исходный флаг проходимости не должен пережить выработку молча.

Разбор с обоснованиями — `docs/PROJECT_GUIDE.md` §3.

## Правовая заметка

Репозиторий приватный. Он содержит **результаты реверс-инжиниринга** коммерческой
игры и извлечённые из её ресурсов данные, модели и текстуры. Права на оригинальный
Diggles, его ассеты, музыку и код принадлежат SEK GmbX / Innonics; авторы проекта
не претендуют на них. Лицензия на код проекта в репозитории не зафиксирована —
использование кода ограничено рамками личного исследования.

Сторонний код: `work/thirdparty/DigglesModManager/` — сторонний проект
(DigglesMods), включён как есть, со своими LICENSE-файлами; его авторство
принадлежит правообладателям этого проекта.

## Инструменты

`tools/` — 72 Python-скрипта: экспорт главы кампании из оригинальных данных
(`export_campaign_chapter.py`), сборка полей земли (`build_ground_field.py`),
аудиты геометрии и текстур, генерация страниц жизненного цикла гнома.
`scripts/` — 21 скрипт для прогонов, патчей и round-trip проверок.

Зависимости: стандартная библиотека Python. Для части аудитов нужен
Python 3.11+; отдельные инструменты читают внешние данные оригинала.
