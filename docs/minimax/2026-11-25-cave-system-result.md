### Этап 2. Модель состояния

Единый словарь `marks` разделён на четыре независимые категории (как требует задание):

- `marked_corridor_cells` — незавершённая разметка тоннеля (`Vector2i → true`);
- `marked_cave_cells` — незавершённая разметка пещеры (`Vector2i → {nibble, group, brush}`);
- `excavated_cells` — клетки, реально переведённые BDB-переходом в открытое состояние;
- `excavated_cave_cells` — открытые клетки завершённой пещеры (`Vector2i → {group, brush}`).

Принадлежность к пещере больше **не выводится** из `block_overrides`: она записывается явно при разметке (`cave_group_cells: Vector2i → group`) и подтверждается при завершении (`excavated_cave_cells`). Добавлены `cave_groups` (кисть, клетки, ожидающие, уровень камеры) и публичный счётчик `marked_count()` вместо обращения к `marks.size()` из сцены. Коридорная геометрия и пещерная рамка разведены: `_decorate_new_passages()` пропускает клетки пещер (`cave_group_cells`), рамка ставится отдельным путём (`_finish_caves()` → `_spawn_cave_frame()`). Статические оригинальные объекты и сгенерированные декорации разделены мета-меткой `generated_decor`.

### Этап 3. Опоры тоннеля

Точное правило оригинала не найдено (в оригинальных шаблонах опоры стоят вручную поставленных автором местах и не образуют сетку — `docs/reverse-engineering/agent-result-campaign-dig-tools-2026-11-25.md`). Реализовано **консервативное** правило, как предписывает задание:

1. Опора ставится только в реально вскопанном тоннеле (`excavated_cells`), а не в незавершённой разметке;
2. Клетки пещер исключены;
3. Опора запрещена, если открыта клетка сверху или её диагонали (то есть верх опоры пересекает открытое пространство);
4. Опора ставится только между открытыми клетками по бокам (стоит в стене прохода);
5. Опора ставится не чаще, чем раз в `SUPPORT_MIN_RUN = 7` клеток непрерывного ряда, и только в середине ряда — не по фиксированной сетке;
6. Опора не ставится ближе `SUPPORT_MIN_DISTANCE = 3.0` клеток к оригинальной или уже сгенерированной опоре — это закрывает «второй ряд опор рядом с существующими»;
7. Используется оригинальная модель `Dummy_Multi_Holzstuetze_*` (копия узла оригинала, 4 меша, исходные материалы);
8. Позиция — центр клетки, высота — по нижней границе модели (AABB), а не по «уровню» клетки: иначе стойка тонет в породе;
9. `_revalidate_supports()` снимает опору, если над ней открылось пространство, и опора не возвращается при следующей разметке.

### Этап 4. Рамка пещеры

Сделан минимальный адаптер `godot/scripts/native_cave_skin.gd` — multiplayer-сцена не переносилась и её публичное поведение не менялось:

- имя скина по кисти: `skin_key(brush, detail) → urw_caves_{1..4}_a_{c|b|a}` (кисть 1…4 → размер 1…4);
- чтение экспортов `res://models/cave_skins/urw_caves_{1..4}_a_a.json`;
- построение мешей повторяет код multiplayer (`OBJECT_WORLD_SCALE = 0.005`, `CULL_DISABLED`, `roughness = 0.95`, текстуры из `res://assets/textures/`) — оригинальные текстуры, не самодельные;
- рамка ставится **только после полного завершения** вскопки пещеры (`_finish_caves()` вызывается, когда очередь пуста), по центру фактически выкопанных клеток, на уровне камеры пещеры;
- рамка не растягивается при зуме (это отдельный узел с фиксированной геометрией, а не спрайт/декаль);
- каждая рамка помечена `generated_decor`, чтобы её клетки не участвовали в коридорном алгоритме опор.

### Этап 5. Очистка и падение объектов

- Прикреплённые к поверхности объекты (`Dummy_Moos`, `Dummy_Multi_Moos`, `Dummy_Gras`, `Dummy_Wurzel`, `Dummy_Liane`, `Dummy_Holzwand`, `Dummy_Multi_Holzstuetze`) скрываются при открытии их клетки;
- свободный дроп падает по оси **Z (высота)**, а не по строкам карты: триггер — собственная клетка объекта, цель — уровень угла `heights[0]` этой клетки;
- объект, под которым нет твёрдого уровня в пределах карты, скрывается, а не падает бесконечно;
- добавлен `processed_objects` — объект обрабатывается один раз, а не на каждом кадре;
- статические объекты вне вскопанного объёма не трогаются (обрабатываются только клетки из `newly_open`).

### Этап 6. Разметка, соединения, стирание, ПКМ

- уже открытые клетки не попадают в новую разметку (`can_dig()` проверяет `heights[0] <= target`);
- пещера без касания тоннеля отклоняется («Пещера должна примыкать к туннелю»);
- стирание снимает пещеру **целиком по группе** (`_erase_cave_group()`) и чистит `cave_group_cells`;
- стирание не трогает уже вскопанное пространство;
- ПКМ по пустому месту снимает инструмент **вместе с нажатым состоянием кнопки** панели (`_choose()` + защита `_choosing` от рекурсии), ESC — то же самое;
- панель инструментов не менялась: 7 оригинальных иконок 40×40 (`BuddelnG`, `BuddelnH0…H3`, `BuddelnUndo`, `Spitzhacke`), без эмодзи и без кнопки «Выбор».

## 5. Какие места остаются приближением

Это честный список: ни одно из этих правил **не** выдаётся за подтверждённое правило оригинала.

1. **Расстановка опор тоннеля.** Точное правило оригинала не найдено. Работает консервативное приближение: одна опора на ряд ≥ 7 открытых клеток, в середине ряда, не под открытым пространством, не ближе 3 клеток к существующим опорам. Числа 7 и 3,0 — приближение, а не факт из оригинала.
2. **Параметр `Set` скина.** Используется линия Set=a / Detail=a (в порте выгружены только `urw_caves_{1..4}_a_a.json`). Семантика `Set` в Tcl оригинала не подтверждена — если оригинал выбирает Set=b или c, нужен дополнительный экспорт.
3. **Высота рамки пещеры.** Ставится на уровень камеры (самая глубокая целевая высота кисти: 3 для кисти 1). В оригинале высота рамки не задокументирована.
4. **Снятие опоры под открывшимся пространством.** Правило «клетка сверху или её диагонали открыты → опора убирается» — консервативное. В оригинале механизм удаления опор при расширении пространства отдельно не документирован.
5. **Требование примыкания пещеры к тоннелю.** Реализовано по заданию («пещера без соединения — должна быть запрещена»), но как правило оригинала не подтверждено.
6. **Порог «открыто» = `heights[0] <= 11`.** Взят из данных BDB и используется в тестах, но в оригинале это сравнение — реверс-гипотеза (см. комментарий в `native_campaign_dig_test.gd:can_dig()`).

## 8. Известные ограничения

1. **Рендер.** В этой среде Vulkan не работает («No render pipeline was set»); кадры снимаются только с `--rendering-driver opengl3`. На обычной машине с Vulkan кадры будут выглядеть иначе по сглаживанию, но геометрия та же.
2. **Папка вывода.** `save_png` требует существующей папки, иначе `error=7` — папка `out/campaign-shots/minimax-2026-11-25/` создана заранее.
3. **Туннель прямо под уже открытым тоннелем в этой карте недостижим.** Вертикальная сетка штриха — 4 клетки, поэтому два тоннеля всегда разведены минимум одной сплошной строкой; оригинальный открытый коридор главы лежит на строках 41–42, а сетка даёт 41–42, 45–46, 49–50… Ни одна клетка под открытой строкой не является копаемой, поэтому правило «опора не ставится под открытым тоннелем» в этой карте срабатывает только через пещеру (кадры 04a/04b) и через юнит-тест `corridor_support_blocked_by_open_upper_space`. Для проверки «тоннель под тоннелем» нужна отдельная тестовая карта.
4. **Диагностические печати** в блоках `--demo-*` остались в сцене — они и есть доказательство для кадров. Они срабатывают только при явном флаге и на обычный запуск сцены не влияют.
5. **Рабочее дерево содержит чужие незакоммиченные изменения** (текстуры стартового мира, шейдер, `native_campaign_ground.gd`, `native_campaign_profile.gd`, два самотеста, `docs/review/...`, `docs/plan/queue-2026-11-19.md`, `model.obj`/`model.mtl` и многочисленные `out/campaign-shots/*.png`). Они не относятся к этой задаче и не трогались. Также `model.obj` и `model.mtl` в корне — мусор от чужой выгрузки; удалять не стал, чтобы не заходить за рамки задания.
6. **Скорость сборки сцены.** Геометрия главы строится ~15 с, объекты ~7 с — это исходная производительность сборки, на работу не влияет.

## 9. Оставшиеся проблемы (по убыванию важности, не более пяти)

1. **Правило расстановки опор оригинала не установлено.** Сейчас работает консервативное приближение (7 клеток / 3 клетки / запрет под открытым пространством). Без реверса правил движка опоры останутся эвристикой, и это главный источник расхождения с оригиналом. Нужен разбор `Diggles.exe` в районе вызова `Dummy_Multi_Holzstuetze`.
2. **Семантика `Set` скина не подтверждена.** Порт везёт только Set=a / Detail=a. Если оригинал выбирает другую линию по уровню материала, оформление пещеры будет отличаться от оригинального. Нужен либо экспорт `urw_caves_*_b_*` / `_c_*`, либо подтверждение, что Set=a — верный выбор.
3. **Высота рамки пещеры не документирована в оригинале.** Ставится на уровень камеры; если оригинал ставит рамку на поверхность или на уровень пола тоннеля, кадр 02/03 будет отличаться.
4. **Механизм удаления опоры при расширении пространства** — консервативное правило (клетка сверху или диагонали открыты). Если оригинал удаляет опору по другим условиям (например, только при снятии целого потолка), поведение будет расходиться на пещерах.
5. **Требование примыкания пещеры к тоннелю** реализовано по заданию, но не подтверждено оригиналом; если оригинал разрешает «висячую» пещеру, ограничение придётся снять.

## 10. Пометка о безопасном откате

**Что можно откатить безопасно:**

- `godot/scripts/native_cave_skin.gd` — **новый файл, ничего не меняет**: удаление файла возвращает систему в состояние «пещеры без рамки». Импортируется только `godot/scripts/native_campaign_dig_test.gd`.
- Блок `--demo-*` в `godot/scripts/native_campaign_first_level.gd` — **чисто диагностический**: он не меняет поведение обычного запуска сцены, его можно вырезать без последствий для геймплея.
- Печать рамки пещеры и правила опор — **логически разделены**: `_spawn_cave_frame()`, `_decorate_new_passages()` и `_revalidate_supports()` — отдельные функции; их можно отключить по одной, не трогая BDB-переходы.

**Что откатить нельзя по одному патчу без потери работы:**

- `godot/scripts/native_campaign_dig_test.gd` и `godot/tools/native_campaign_dig_test.gd` — **оба файла были untracked до начала работы** (в git их нет), и их прежнее содержимое нигде не сохранено. Их до-рабочие версии можно восстановить только из резервной копии OneDrive, а не из git.
- `godot/scripts/native_campaign_first_level.gd` — файл содержит и чужие правки, поэтому `git checkout --` на нём откатит чужую работу.

**Рекомендуемый порядок (одна команда после фиксации состояния):**

1. Зафиксировать текущее состояние: `git add godot/scripts/native_cave_skin.gd godot/scripts/native_campaign_dig_test.gd godot/tools/native_campaign_dig_test.gd godot/scripts/native_campaign_first_level.gd docs/minimax out/campaign-shots/minimax-2026-11-25` и один коммит — **это ещё не сделано, коммит не создавался** (задание не требовало коммита, и в дереве лежат чужие незакоммиченные изменения).
2. После этого откат всей этой работы = `git revert <коммит>` или `git checkout <коммит>^ -- <5 файлов>` — то есть действительно один патч.
3. Откат только визуальной части (рамки пещеры) = вернуть `_spawn_cave_frame()` в неактивное состояние; откат только правил опор = отключить `_decorate_new_passages()`.

**Быстрый «мягкий» откат без git:** удалить `godot/scripts/native_cave_skin.gd`, вырезать блоки `--demo-*` из сцены и вернуть `marked_count()` → `marks.size()` в вызывающем коде; сцена запустится, но пещеры останутся без рамки, а опоры — по старой эвристике.
