# Генератор уровня оригинала: пещеры, туннели, месторождения

Дата: 21.11.2026 (обновлено: правила восстановлены из декомпиляции Diggles.exe)
Сессия: отдельная (SideChat), вне работ Main Chat (порода/гранит/свет главы) и
основного чата (грунт/освещение/геометрия поверхности).

## 0. Что это и зачем

В оригинале карта зоны — не файл и не список шаблонов, а результат работы
**генератора уровня** движка (`lg_start`). Зона карты делится на участки, и
каждый участок наполняется сгенерированным уровнем: цепочкой туннелей, пещерами
рядом с ними и объектами классов ресурсов.

В порте этого нет вообще: глава собирается только из шаблонов `first_level`
(`Campaign.tcl:22-191`) и из рукописных сюжетных пещер зоны
(`CampaignInit.tcl:110-188`). Это 38 шаблонов на 15 709 клеток — 4.8 % карты
512×640. Остальное — пустой базовый слой.

Задача блока: **восстановить правила генератора уровня оригинала и порт их
детерминированно**, с проверяемым результатом (план уровня → выгрузка → кадр).

Размеры шаблонов (заголовок их pmp): туннели 4×4…28×16, пещеры 16×8…48×24,
концы 4×4…20×16.

### 1.2 Синтаксис группы — `Scripts/init/lgtools.tcl:4-56`

* Пул семьи = glob по файлам; элемент с заглавной буквы — вложенная группа.
* Для группы с `.hol` и `.gsg` в имени движок ставит `-levelcount 1`
  (`lg_set_templategroupprops`): **каждый** шаблон такой группы — один выкопанный
  уровень (нативная проверка `LGSetTemplateGroupProps` раздаёт свойство всем
  шаблонам группы, а не группе целиком).
* `LG_set_templateprops` (`lginit.tcl:46-51`) задаёт для шаблона счётчик игр,
  число уровней и вес туннеля:

```
{urw_gng_050_a 1 1 -}   {urw_gng_051_a 1 1 -}   {urw_gng_052_a 1 1 -}   {urw_gng_054_a 1 1 -}
```

### 1.6 Как запускается генератор — `story.tcl:92-105`, `story.tcl:199-208`

```
lg_tp_clear
lg_tp_addtemplatesets " $zone.Std "
lg_tp_objfilter { Troll Zwerg }
lg_set_area $xn $yn $xp $yp
set ratio    [expr 1 - (abs($midx - ($xn / $resolution)) / $midx)]
set optratio [expr $ratio / 2.5]
set optratio 0.10
lg_set_templateratio 0 $optratio 1
lg_set_leveltype base
lg_start
set level [lg_get_level]
fill_temp_buffer $level      ;# lg_sort_level — сортировка уровня
```

Плюс `lg_set_objcount $item 0 $diff_oc 32` (`story.tcl:83`) — движок **добивает**
недостающие объекты классов до нормы зоны.

`$resolution` — это `sm_get_resolution` движка, значение **4**: клетка карты
делится на четыре клетки генератора. Участок зоны (`sm_get_level_info`) дан в
клетках карты, а `lg_set_area` получает его в клетках генератора (×4).

### 1.7 Нативный алгоритм `lg_start` — из декомпиляции Diggles.exe

Источник: выгрузка Ghidra `C:\diggles-ghidra\out\decomp` (11 373 функции;
индекс — `work/campaign/ref/ghidra-out/index.tsv`). Имена методов движка
восстановлены по assert-строкам, поэтому нужные команды опознаны точно.

| Что | Функция | Поведение |
|---|---|---|
| `lg_start` | `CTclGlobalMethods__LGStart` 0x00652bc0 | создаёт объект генератора, готовит сетку участка, раскладывает шаблоны, пишет их в карту |
| `lg_set_area` | `FUN_00583ac0` | участок отступается на 8 клеток от границ карты и выравнивается по сетке 4; `x0,y0` — вверх, `x1,y1` — вниз |
| `lg_tp_clear` | `FUN_00583650` | ставит **зону отступа 4 клетки** (`+0x80 = 4`) и обнуляет счётчики |
| `lg_set_templateratio` | `CTclGlobalMethods__LGSetTemplateRatio` | `+0x74` = доля (optratio), `+0x78` = предел (ratio), `+0x70` = первый аргумент |
| сетка участка | `FUN_00583c60` | клетки, занятые в карте, становятся занятыми; клетки у края карты — тоже |
| «неполные» блоки | `FUN_00583df0` | блок 4×4, в котором есть хоть одна занятая клетка, помечается особым значением |
| **размещение** | `FUN_005842c0` | позиция кратна 4 (`(x \| y) & 3 == 0`), блок шаблона должен лежать на свободных клетках, вокруг него резервируется **зона отступа 4 клетки** на сторонах, где нет точки соединения |
| **оценка** | `FUN_00586710` | меньше — лучше: `\|20 − (ширина+высота)\|`, число точек соединения (цель 3 → 2,5 → 2 → 1 по мере заполнения), число использований шаблона, вес шаблона, случайная добавка |
| следующий туннель | `FUN_005862c0` | первый шаблон — 4×4 с двумя точками соединения; место — до 16 попыток случайной точки на сетке 4 |
| точки соединения | `FUN_00583f60` | точки соединения поставленного шаблона становятся открытыми концами; конец, на который попала новая точка, закрывается |
| группы | `FUN_00587480` | группа (пещеры, галереи) ставится один раз, шаблон внутри группы выбирается по весам |
| **загрузчик `.ent`** | `FUN_005826d0` | читает файл точек соединения набора: берёт только точки вида 1, переносит точку в блок шаблона и **выводит сторону точки из её места**: `x = 0` → левая, `x = ширина` → правая, `y = 0` → верхняя, `y = высота` → нижняя |

Точки соединения лежат в файлах `data/Templates/<набор>.ent` и читаются так:

```
map_entry 1 0 16      ;# gng_001.ent - точка вида 1
map_entry 1 32 16
```

Формат: `map_entry <вид> <x> <y>`, координаты — в единицах, где блок шаблона
занимает 8 единиц. Натив переводит их в клетки генератора: `x = (x/8)`, округлённый
вниз по сетке 4, с добавлением 2 внутри блока 4×4.

**Итоговые правила раскладки (факт):**

1. Позиция шаблона кратна 4 по обеим осям.
2. Блок шаблона не накладывается ни на что занятое.
3. Вокруг шаблона резервируется 4 клетки на каждой стороне, где у него **нет**
   точки соединения; там, где точка есть, сосед примыкает вплотную.
4. Уровень наполняется до своей доли площади участка (`optratio`), но не больше
   предела (`ratio`).
5. Шаблон выбирается оценкой: размер около 20 клеток, число точек соединения по
   состоянию заполнения, малое число использований.
6. Цепочка растёт от открытых концов: следующий шаблон ставится так, чтобы его
   точка соединения легла на открытый конец (стороны противоположны).

## 2. Что сделано в порте

### 2.1 Инвентарь шаблонов

`tools/build_level_template_inventory.py` → `godot/models/native_level_templates.json`
(301 КБ): по установке собираются настоящие имена шаблонов, размер их карты
(заголовок pmp), классы их объектов **и точки соединения** — те же, что читает
натив (`FUN_005826d0`), с выводом стороны точки из её места. Проверено на всех
645 шаблонах четырёх миров: у каждого есть точки, и ни одна не выходит за границы
блока.

### 2.2 Генератор

`godot/scripts/native_level_generator.gd` — правила и раскладка:

* данные групп, долей пещер, норм ресурсов, фильтра и точек соединения читаются
  из инвентаря;
* случайность — восстановленный из Diggles.exe MT19937
  (`NativeCampaignLevel.DigglesRandom`, тот же, что у главы);
* участок: отступ 8 клеток от границ карты и выравнивание по сетке 4 (§1.7);
* первый кусок — шаблон 4×4 с двумя точками соединения, место ищется 16 попытками
  случайной точки;
* цепочка растёт от открытых концов: для каждого конца оцениваются все шаблоны
  пула (правила §1.7), лучший ставится так, чтобы его точка легла на конец;
* зона отступа 4 клетки резервируется вокруг каждого шаблона на сторонах без
  точек соединения;
* уровень добирает свою долю площади (`optratio` = 0.10 от `story.tcl:202`) и не
  превышает предел (`ratio` = 1.0);
* группа пещер зарегистрирована для каждого мира — в уровне одна пещера, рядом с
  цепочкой, с тем же отступом;
* галерея (Gsg) закрывает свободный конец цепочки, если там есть место;
* ресурсы зоны (Urwald — 12 грибов) кладутся на пол пещер.

Факт: составы групп, имена и размеры шаблонов, точки соединения, доли, нормы,
классы фильтра, правила сетки, отступа, заполнения и оценки.
Адаптер: обход открытых концов и выбор шаблона — те же правила, но не та же
последовательность, что в оригинале; место пещеры — рядом с цепочкой (прямоугольник
группы в нативе не восстановлен).
Неизвестно: условие остановки натива (§6).

### 2.3 Выгрузка

`tools/export_generated_level.py` — берёт штатный экспортёр главы как модуль
(`export_campaign_chapter`) и подменяет ему список размещений планом
генератора: та же вычитка pmp/l2m, те же блоки BlockDB, тот же атлас деталей.
Ресурсы зоны (грибы Urwald) ставятся на поверхность клеток пещер, их высота
берётся из блока. Источники света не имеют моделей, поэтому их места
добавляются в манифест — иначе пещеры остались бы тёмными.

### 2.4 Превью

`godot/scripts/native_generated_level_preview.gd` + `godot/scenes/generated_level_preview.tscn` —
та же местность главы (профиль, грунт, стены выработок, шейдер), но уровень
сгенерированный. Свободный грунт вокруг не рисуется: план породы главы — это
воронка из сейва, она принадлежит сцене главы.

## 6. Что осталось (не сделано и почему)

* **Условие остановки натива.** Скрипты называют первый аргумент
  `lg_set_templateratio` «оптимальной долей», а второй — пределом; натив
  использует первый для выбора шаблонов, второй как жёсткий предел. Порт
  останавливает уровень, когда достигнута доля, — это адаптер, а не факт.
* **Проверка открытого конца** в `FUN_00584120` (свободна ли клетка и её
  окрестность) в декомпиляте противоречит разметке блока шаблона, и свести её
  однозначно не удалось; в порте проверяется, что блок нового шаблона не ложится
  на зону отступа предыдущего.
* **Прямоугольник группы** (`FUN_00587480`), в который натив ставит пещеру и
  галерею, не восстановлен; в порте пещера копается рядом с цепочкой.
* **Прямоугольники участков зоны** (`sm_get_level_info`) — тоже движок; в порте
  участок задаётся параметром.
* **Свободный грунт вокруг сгенерированного уровня** — план породы главы
  (воронка из сейва) принадлежит сцене главы; здесь не применяется.
* **Порода под уровнем** — в превью нет тела породы: блок «рельеф породы» и
  грани в плоскостях `x = const` открыты в `queue-2026-11-19.md` §0.12 и
  принадлежат другому кругу работ.
