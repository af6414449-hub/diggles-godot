# Diggles: свободная камера (панорамирование) и расширенный зум

Дата: 2026-11-23
Задача (от пользователя, 23.11): «разрешить перемещать камеру не только за пределы
вскопанных областей + отдалять дальше, чем текущий максимальный zoom».

Все утверждения помечены: **факт** (прочитан в байт-коде), **адаптер** (вывод),
**неизвестно**.

---

## 1. Модель камеры (факт)

### 1.1 Поля камеры

Объект камеры: `DAT_00772400 + 0x5a4` (указатель, `app+0x5a4`).

| смещение | содержимое |
|---|---|
| `+0x134/+0x138/+0x13c` | «запрошенный» вид (x, y, zoom) — пишет `set_view` |
| `+0x140` | bool: камера следует за объектом |
| `+0x144` | float |
| `+0x148` | byte |
| `+0x14c/+0x150` | ptr (позиция «камеры-слота») |
| `+0x154` | **x камеры** (float, мировые единицы) |
| `+0x158` | **y камеры** |
| `+0x15c` | **zoom** |
| `+0x160/+0x164` | наклон / поворот |
| `+0xf4…+0x120` | сглаженные (текущие) значения вида |

`get_view` возвращает 5 чисел: x, y, zoom, наклон, поворот.
`set_view x y zoom tilt rot` — тоже родная команда Tcl (см.
`agent-result-keybind-camera-2026-11-22.md` §4).

### 1.2 Границы камеры = «вскопанная область» (факт)

Прямоугольник камеры лежит в `app + 0xa328 + owner*0x10` — 4 int
`[x0, y0, x1, y1]` **в ячейках карты** (ячейка = 8 мировых единиц).

* Читают его только **два клампа камеры**:
  `FUN_00529570` (основная камера, мышь/колесо) и `FUN_00529C10`
  (второй экран/мини-карта). Плюс его же переписывают writers тумана.
* `FUN_00529570` клампит:
  * `camX` в `[rect[0]-1, rect[2]+1]`, `camY` в `[rect[1]-1, rect[3]+1]`;
  * если мышь вне этого диапазона — камера «отскакивает» в середину прямоугольника.
* Прямоугольник **растёт** по мере снятия тумана:
  `CFogOfWar::RemoveFogLine` (`0x0057EA10`), `RemoveFogBoxNoCollision`
  (`0x0057F170`), `RemoveFog` (`0x0057E120`) делают
  `rect[0]=min(rect[0], x0)`, `rect[1]=min(rect[1], y0)`,
  `rect[2]=max(rect[2], x1)`, `rect[3]=max(rect[3], y1)`
  (в ячейках, с обрезкой по границам карты).
  → это и есть «вскопанная область»: bounding box исследованного.
* **Ветка «показать всю карту»** (`CFogOfWar::UpdateFoW`, `0x0057F5C0`,
  адрес `0x0057FB00`) заполняет эти же 8 прямоугольников **полными
  границами карты**: `map+0x84..0x93` (`DAT_0077241c+0x84`), т.е. `[x0,y0,x1,y1]`
  в тех же единицах. То есть движок уже умеет «отпустить» камеру на всю карту.

### 1.3 Позиция камеры всё равно ограничена картой (факт)

`FUN_00475EE0` (построитель вида, вызывается из `CGameThread::Draw` по адресу
`0x006B6A6A`) клампит `*param_1`/`*param_2` (это `&camX`, `&camY`) по
`map->cellX0 … cellX1` и `map->cellY0 … cellY1` (а также по полям
`x0f/y0f/x1f/y1f` карты). Поэтому «за пределы карты» камера не уедет —
и это правильно: задача = «за пределы *вскопанной* области», т.е. по всей карте.

### 1.4 Зум (факт)

* `CGameThread::Draw`, адрес `0x006B6968`, клампит зум:
  `zoom = min(2.5, max(1.0, zoom))` — константы `0x737138` = 1.0 и
  `0x7373d8` = 2.5. **Это и есть «текущий максимальный zoom»** (1.0 — самый
  отдалённый).
* Вторая ветка того же кода (при `app+0x598 != 0`) использует диапазон
  `[0.5 … 6.0]` — т.е. движок сам использует 0.5 как «широкий» минимум.
* Зум пишется: колесом (`zoom *= f_a8`, `FUN_00529570`), клавишами J/O
  (`zoom ± 0.5`, `FUN_0052C510`), `set_camera_follow` (кламп 0…2.5).

### 1.5 Множитель панорамирования (факт, важно)

`FUN_00529570` считает скорость панорамирования:

```
fVar12 = (zoom - 1.0) * app->0x198 * 0.2 + 1.0
```

`app+0x198` — значение опции **«Brightness»** (реестр `HKCU\Software\SekOst\
Diggles\Screen\Brightness = 50`), т.е. `fVar12 = (zoom-1)*10 + 1`.

Следствие: при `zoom < 0.9` множитель становится **отрицательным**, и
панорамирование (скорость = `20 * fVar12 / zoom` единиц за кадр) инвертируется.
Значит одного расширения диапазона зума недостаточно — нужен ещё кламп.

## 2. Что наложено (адаптер)

Файл: `work/thirdparty/DigglesModManager/patch-camera.py`
(наложение / `--check` / `--revert`).

### P1 — прямоугольник камеры = границы карты

* Хук: `CGameThread::Draw`, **VA `0x006B6A75`** — инструкция
  `mov eax, [0x77241c]` (5 байт) заменена на `call` подпрограммы.
  Подпрограмма возвращает `eax = [0x77241c]` — поведение идентично.
* Подпрограмма (code cave, **VA `0x0071493A`**, 80 байт) каждый кадр
  копирует `map+0x84..0x93` → `app+0xa328 … app+0xa3a7` (все 8 владельцев),
  т.е. ровно то, что делает ветка «показать всю карту».
* Code cave — свободные 198 байт в конце секции `.text`
  (`VS=0x31393A`, raw=0x313A00; байты нулевые), VA `0x0071493A`,
  файловые смещения `0x00313D3A` … `0x00313DF8`.

### P2 — минимальный зум 0.5 (было 1.0)

`VA 0x006B6968`: `movss xmm6, [0x737138]` → `movss xmm6, [0x73708c]`
(адрес константы 1.0 меняется на уже существующую в `.rdata` 0.5).
Диапазон зума → **[0.5 … 2.5]**.

### P3 — защита множителя панорамирования

`VA 0x00529611`: `mulss xmm5, [esi+0x198]` → `call` подпрограммы
(VA `0x0071498A`, 13 байт):

```
maxss xmm5, xmm7      ; xmm7 = 0 в вызывающем коде -> xmm5 = max(zoom-1, 0)
mulss xmm5, [esi+0x198]
ret
```

Для `zoom >= 1.0` поведение **не меняется вообще**; для `zoom < 1.0`
множитель не уходит в минус (панорамирование не инвертируется).

## 3. Что проверял пользователь (нужно сделать)

1. Запустить игру (нужен перезапуск — exe изменён).
2. **Панорамирование**: увести камеру мышью/краем экрана в неисследованную область
   (чёрный туман) — камера должна поехать, а не отскочить к центру
   вскопанной области. За пределы *карты* камера по-прежнему не уедет.
3. **Зум**: отдалить максимально — должен получиться диапазон до 0.5
   (в 2 раза шире, чем было). Проверить, что колесо/клавиши J-O работают.
4. Скорость панорамирования (edge-scroll и перетаскивание) не должна была
   измениться при зуме ≥ 1.0 — если ощущается иначе, сообщить.

Откат: `python patch-camera.py --revert` (или вернуть `Diggles.exe.camera.orig`).
