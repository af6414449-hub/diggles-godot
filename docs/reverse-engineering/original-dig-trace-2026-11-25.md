Порт сейчас ставит одну опору на весь непрерывный пробег (`SUPPORT_MIN_RUN=7`, середина пробега). Следовательно, текущая плотность/позиции опор — известный ADAPTER с расхождением от оригинала. Выравнивание визуальной области по 4 клеткам нельзя превращать в правило появления опор.

## FACT: выбор образца визуализации карты

В [FUN_0058a8b0_0058a8b0.c](evidence/FUN_0058a8b0_0058a8b0.c) движок перебирает зарегистрированные образцы визуализации, проверяет размеры образца (`width*height < 17`), сопоставляет его числовую матрицу с областью карты, собирает подходящие варианты и выбирает один через `FUN_0049c670`. Там же есть проверка истории выбранных вариантов. **Эта функция не выбирает Tcl-шаблон прохода.**

Образец загружается лениво: [FUN_00581b40_00581b40.c](evidence/FUN_00581b40_00581b40.c) открывает путь, записанный у зарегистрированного образца, и передаёт файл в [FUN_00599fc0_00599fc0.c](evidence/FUN_00599fc0_00599fc0.c). Загрузчик читает `int32 width`, `int32 height`, затем `width*height` байт и `width*height` 32-битных ID блоков; по ID берёт низкий нибл флага из BlockDB и строит двоичную матрицу признака `== 0xb`. Формат префикса совпадает с `.pmp`, но путь конкретных образцов пока не извлечён. Сканирование файлов оригинала по **точной длине** этого префикса не даёт файлов, потому что `.pmp` имеют дополнительные секции.

## FACT: живые опоры и корни происходят из оригинальных шаблонов

[match_template_placements.py](../../tools/dig_trace/match_template_placements.py) сопоставляет класс и финальные XYZ из `object_snapshot` с объявлениями `new` в оригинальных `data/Templates/urw_gng_*.tcl`, `urw_hol_*.tcl`, `urw_unq_start.tcl`. Он требует целое смещение X/Y, кратное 4, и погрешность менее 0.02 по X/Y, 0.04 по Z. Для свежего прогона нашёл хотя бы одно совпадение для **21 из 21** уникальных позиций: 9/9 опор, 10/10 кустов мха, 2/2 корня; 19 имеют ровно одно совпадение, два — по два возможных шаблона. Для 19 подходит `urw_gng_*`; остальные соотносятся с готовой пещерой и стартом. Позиция в шаблоне подтверждает источник модели/координат, но сама по себе не доказывает, в какой момент объект был создан или стал видимым.

## FACT / ADAPTER: что уже есть в порте и что исправлено

`tools/export_campaign_chapter.py` уже экспортирует объекты из Tcl-шаблонов в `native_campaign_chapter.json`, а `native_campaign_first_level.gd:_build_objects` создаёт их при загрузке главы. Но `native_campaign_dig_test.gd:_settle_objects` скрывал каждую исходную опору при первом открытии клетки рядом с ней. Это прямо противоречило живому появлению опор в открытом ходе. Теперь исходная опора сохраняется при выкапывании туннеля; при завершении пещеры скрывается опора, чья точка привязки попала в её клетки. Последнее по времени остаётся ADAPTER: оригинальный журнал видел исчезновение ещё во время копания. Нынешняя дополнительная опора «одна на пробег» также остаётся ADAPTER до восстановления её реального источника.
